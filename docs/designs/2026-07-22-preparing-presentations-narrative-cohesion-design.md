# Preparing Presentations 叙事连贯性改进设计

> 状态：待实现。

## 1．反馈背景

`preparing-presentations` 第一版覆盖了目标、听众、叙事设计、分章共创、完整讲稿、故事板、素材、最终载体和排练，但一次真实长分享暴露出三个相关问题：

1. 章节虽然存在，边界和职责不够清晰；缺少明显章节幕封、章节结束总结以及通往下一章的桥接。
2. 相邻页面在内容上有关，但讲稿没有稳定承载“为什么从上一页来到这一页”，导致切页时像在切换话题。
3. 结尾缺少全场路线回顾，听众难以在结束前重新抓住各阶段重点和最终行动。

这些问题共同说明：第一版更擅长检查单个章节和单个页面是否完整，对跨章节、跨页面和全场收束的连接约束仍然偏弱。

## 2．目标

增强 Skill 对三个叙事层级的约束：

```text
全场主线
→ 章节闭环与接力
→ 相邻页面之间的承接
```

改进后的 Skill 应当让标准和完整模式的演讲具备清晰章节边界、可口述页面过渡和帮助听众重建全场地图的结尾回顾，同时不把轻量分享变成形式化流程。

## 3．设计原则

### 3.1 章节是叙事单元，不是内容文件夹

每章都应回答一个明确问题，并形成：

```text
提出本章问题
→ 展开内容和证据
→ 得出本章结论
→ 解释为什么进入下一章
```

### 3.2 页面过渡必须能说出口

“与前后页相关”不构成完成标准。故事板或讲稿需要给出演讲者能够直接使用的承接或引出方式。

### 3.3 回顾不是重放目录

结尾回顾应将各章压缩为一条推进链，重新落回核心命题，并给出听众下一步行动，而不是逐字重复章节标题。

### 3.4 不机械增加页面

轻量模式不强制章节幕封或独立章节总结页。标准和完整模式默认规划章节幕封；章节总结可以通过最后一页的讲述内容完成，不强制每章额外增加一页。

## 4．产物契约改进

### 4.1 大纲与章节记录

`outline.md` 中每章增加：

- 本章要回答的问题；
- 本章最终结论；
- 与上一章的关系；
- 通往下一章的桥接；
- 是否需要章节幕封。

分章记录增加明确的章节闭环：

- 开场句或开场问题；
- 本章结论；
- 一到三条章节回顾；
- 下一章桥接句。

### 4.2 故事板

每页在现有页面目标、核心信息和视觉形式基础上增加：

- `承接上一页`：上一页留下的哪个问题、结论或视角带到本页；
- `本页角色`：本页在“问题／回答、现象／原因、方法／案例、全景／局部、方案／结果、成功／局限、当前／未来”等关系中承担什么作用；
- `引出下一页`：本页结束时留下什么问题、判断或悬念；
- `过渡句`：需要时给出一条可以直接说出口的过渡。

首尾页和章节幕封可使用“不适用”，但不能用空字段掩盖相邻内容没有关系。

### 4.3 完整讲稿

讲稿必须承载：

- 章节开场定位；
- 章节结束的小结和桥接；
- 相邻页面之间的自然过渡；
- 结尾的全场路线回顾、核心命题和下一步行动。

不要求每页使用固定句式；过渡应服务于真实逻辑关系，而不是重复“接下来我们看”。

### 4.4 结尾

标准和完整模式在进入 Q&A 或结束页前，默认安排整体回顾。至少包含：

1. 回到开场问题或核心命题；
2. 用三到五个节点复述全场推进路线；
3. 压缩出听众最应该记住的结论；
4. 给出一个可执行的下一步。

轻量模式可以用一页或一段话完成，不强制单独制作回顾页。

## 5．协作规则改进

逐章确认时，在原有目标、依据、例子和过渡四问之外，增加两项显式检查：

- 本章结束后，听众能用哪一到三句话概括本章；
- 为什么下一章必须在此时出现。

故事板评审不只逐页确认，还要执行“相邻页串读”：连续朗读上一页结尾、本页过渡和下一页开头，判断是否像同一段表达。

全稿完成后执行“骨架串读”：只读取章节开场、章节结论、章节桥接和最终回顾，检查是否仍能还原整场分享逻辑。

## 6．质量 Gate 改进

### 6.1 章节边界 Gate

标准和完整模式检查：

- 章节开始是否让听众知道当前位置和本章问题；
- 是否规划章节幕封，或有同等清晰的口头定位；
- 章节结束是否归纳一到三条结论；
- 是否解释下一章为什么自然出现。

### 6.2 页面连接 Gate

检查：

- 每对相邻页面能否说明逻辑关系；
- 讲稿是否包含必要的承接和引出；
- 是否存在连续多页仅靠标题切换话题；
- 过渡是否具体，而非反复使用“下面看一下”。

### 6.3 结尾回顾 Gate

检查：

- 是否回到开场问题或核心命题；
- 是否沿全场路线回顾各阶段重点；
- 是否给出最终结论和听众下一步行动；
- 是否在 Q&A 前完成内容收束。

## 7．回归场景

### Case E：长分享但不想增加章节页

用户已有四章、28 页的 60 分钟分享，并要求“不想增加页面，直接完善”。验证 Skill 是否区分“必须有章节边界”和“必须新增章节页”，提出幕封或口头定位的最小方案，并补齐章节小结与桥接。

### Case F：页面内容正确但切换生硬

用户提供六页逻辑相关但缺少过渡的故事板。验证 Skill 是否逐对识别页面关系，并将过渡落入讲稿，而不是只说“加强衔接”。

### Case G：最后一页直接进入 Q&A

用户认为内容已经讲完，最后一页只有“Q&A”。验证 Skill 是否建议在 Q&A 前增加全场路线回顾、核心结论和下一步行动，同时避免机械重复目录。

## 9．非目标

- 不为轻量分享强制增加章节幕封页；
- 不要求每章单独增加总结页；
- 不为每一页强制写模板化过渡句；
- 不修改 PPT 视觉生成实现；
- 不改变第一版已经通过验证的自适应入口、产物裁剪和手工接管规则。

## 10．完成标准

1. Case E～G 在现有 Skill 下先形成真实 RED 基线；
2. 四个 Skill 文件完成最小修改；
3. Case E～G 在更新后无硬失败；
4. 原有 Case A～D 的关键规则不回退；
5. 官方 Skill 校验和占位符检查继续通过。
