# Preparing Presentations

## 核心原则

先识别已有内容的成熟度，再决定从哪个阶段接入。先设计表达，再制作载体；只创建完成当前分享所需的最小产物集合。

## 适用边界

适用于技术分享、经验分享、培训课程和主题演讲。不用于项目汇报、方案评审、述职、销售提案或融资路演。

## 开始前

1. 盘点已有主题、资料、大纲、讲稿、故事板、素材、现场演示和最终文件。
2. 识别当前最合适的接入阶段，已明确的信息不得重复询问。
3. 信息不足时，一次只问一个当前最关键的问题，并给出推荐选择和理由。
4. 选择轻量、标准或完整模式。创建任何文档前读取 `references/artifact-contracts.md`。

用户要求直接制作 PPT 时，先判断目标、听众、时长、核心内容和素材是否足以支撑成稿。信息足够则执行；信息不足则只询问阻塞性问题，不用未经确认的假设补齐关键决策。

## 工作流

从与现状匹配的阶段开始，不强制重走前序阶段：

0. **入口判断**：盘点现有内容，选择接入点和产物模式。
1. **分享简报**：确认目标、听众、场景、时长、带走内容和不讲什么。
2. **叙事设计**：确定核心命题、主线、优先级、章节问题、章节关系和时间预算。
3. **分段共创**：逐段讨论目标、依据、例子或互动、结论、回顾和下一章桥接。
4. **完整讲稿**：组合已确认内容，处理口语化、章节闭环、逐页过渡、全场回顾和现场动作。
5. **故事板与素材**：定义每页任务、前后页关系、可口述过渡、视觉形式、备注、素材和演示方案。
6. **演示产物**：按用户选择生成或编辑 PPTX、网页、讲稿或提词卡。
7. **排练与交付**：核对时间、压缩顺序、Q&A、演示切换和风险。

推进讨论、章节确认、用户跳步或手工接管时，必须读取 `references/facilitation-playbook.md`。

## 硬性规则

- 复杂分享按章节推进。未经用户明确确认，不得把章节标记为“已冻结”或并入最终讲稿。
- 标准和完整模式必须具有清晰章节边界。默认规划章节幕封；用户不希望增页时，用同等清晰的口头定位替代。
- 每章都要形成“本章问题 → 内容与证据 → 一到三条结论 → 下一章桥接”，不能只是内容分组。
- 故事板和讲稿必须说明相邻页面的逻辑关系，并在需要时给出可直接说出口的过渡。
- 长分享进入 Q&A 或结束页前，必须回顾全场推进路线、核心结论和听众下一步行动；不机械重放目录。
- 外部事实、个人经验、当前探索和未来设想必须分开表达；外部事实优先查一手来源。
- 主动指出内容过多、概念过密、案例重复和时间失衡，并给出具体删减建议。
- 用户主动跳过阶段时说明风险并记录选择，不强迫补齐。
- 内容不足时，不得伪装成已经可以生成最终载体。
- 用户手工修改最终文件后，该文件成为新的事实来源；未经确认不得重新生成或覆盖。
- 需要创建或编辑 PPTX 时，使用 `presentations` Skill，不在本 Skill 中复制幻灯片生成流程。
- 阶段结束、生成最终产物或交付前，必须读取 `references/quality-gates.md` 并执行对应检查。

## 完成标准

完成不是“文件已经生成”，而是内容可讲、节奏可控、证据边界清楚、演示可执行，且用户确认当前交付物符合目的。保留分享者本人的语言风格，避免模板化的 AI 腔。
