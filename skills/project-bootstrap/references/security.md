# 安全基础

## 适用条件与职责

初始化或补齐工程的认证授权、HTTP 与浏览器防护、不可信输入及外部访问、资源限制、执行隔离或安全检查时读取。先识别暴露面和信任边界，再实现适用控制；库、静态前端及一次性工具落实各自边界，不为使用本模块额外建立登录服务、权限平台或 HTTP 入口。

新建 REST 服务的业务接口默认受保护，公开接口显式声明；认证方式按工程选择，已有工程沿用有效方案，仅补齐实际缺项。MCP 等专门协议另行维护，不套用 REST 认证与响应约定。

本模块维护通用安全要求及适用条件，以下规则继续由原模块负责：

## 规范与要求

### 入口与访问控制

- 清点所有实际监听端口、路由和独立进程，包括框架附带的接口、文档、调试及管理入口。逐项明确保护方式、公开范围及负责人，主服务认证不自动覆盖其他进程或入口。
- 新增业务路由默认进入统一访问控制，公开入口显式声明；复用团队身份系统、框架或既有代理接入，不预置 JWT、Session、API Key、RBAC 或自建账号体系。探针和指标入口保留所属模块的运维规则，由实际环境限制访问。
- 认证确定调用者身份，授权检查当前动作及资源范围，覆盖适用的用户、租户、项目和数据归属。前端导航、按钮和 capability 只控制交互，服务端始终执行必要授权；不可猜测的 ID 不代替资源授权。
- 授权覆盖实际执行入口，包括 AI 工具、SDK 内部接口及启用认证的本地替身中的受保护操作，逐项核对运行、重连、历史读取和停止。身份经过主接口验证不等于其他路径已接通；工具参数、模型指令和客户端标识也不能替代动作与资源授权。
- 身份来自已验证凭据或明确可信的上游，不从普通请求头、正文、页面或 AI 上下文直接建立授权身份。依赖上游控制时记录信任来源、身份传递及防绕过条件，并核对实际接入。
- 执行时缺少必要可信身份或授权上下文则拒绝受保护操作；独立后台工作采用明确的服务身份或有效授权，不机械要求存在 HTTP 用户请求。日志上下文仅用于诊断，记录了用户或关联标识不构成授权证明；可信身份可复用工程上下文设施，不强制采用某种存储机制。
- 缺少凭据、凭据无效或无法确认必要权限时拒绝访问，不降级为匿名或默认管理员；具体错误语义沿用错误处理模块。必要认证配置缺失在启动前失败，测试身份和跳过认证等旁路只在显式开发或测试条件下启用，正式环境误启用时启动失败。

### 身份、会话与跨服务调用

- 凭据校验、有效期、撤销和密钥轮换复用所选成熟方案，具体时长及组件按工程确定。轮换明确新旧密钥的接受范围和旧密钥退出条件，不把支持多个 key ID 当作轮换已接通。
- 接入外部登录时由成熟协议库完成适用的签名、签发方、接收方、时间和登录事务校验。OAuth／OIDC 按协议落实 PKCE、state、nonce 等适用保护，登录回调的匿名可达不代表可以跳过事务验证；回调地址使用已认可配置，登录后跳转限制为认可的站内目标或显式允许范围。
- 外部身份与内部账号分开建模，OIDC 的 issuer＋subject 映射内部用户，外部 subject 不直接冒充内部 ID。邮箱关联、自动开户及账号合并按业务明确，使用具备可信验证语义的属性，不能仅凭一个邮箱字段自动绑定账号。
- 有动态账号和权限管理时，停用与撤权默认在下一次受保护操作生效；采用缓存时明确最大生效延迟，高风险操作按需重新检查。不得只依赖登录时快照；不为此强制每个工程建立用户表、Redis 或新权限系统。
- 退出明确服务端会话失效或所选无状态方案的剩余有效窗口，清除浏览器 Cookie 不作为旧令牌已失效的证据。前端收到认证或权限拒绝后清理相关敏感缓存、刷新身份或权限视图，不继续展示失去权限的数据。
- 跨服务代用户操作时分别验证服务身份和用户授权，普通用户 ID 或邮箱请求头不能独立证明授权，下游保留最终领域及资源授权。需要签名断言时绑定主体、动作、目标、用途和有效期，接收方验证适用算法、签发方、接收方、类型及请求匹配；协议及算法不照搬某个参考工程。

### HTTP 与浏览器防护

- 正式环境对外使用 HTTPS，TLS 可由网关或负载均衡终止；应用与平台间的连接及信任前提明确。对外调用保持证书校验，不通过全局关闭校验处理证书或代理问题。
- 转发头仅接受明确可信的代理来源或链路，核对来源 IP、协议、Host 及身份信息的使用条件。实际 TLS、网络和代理配置按构建交付模块交接给外部平台，仓库不执行部署。
- 没有跨域需求时默认不开 CORS；需要时明确允许的来源、方法和请求头，携带凭据时不任意反射来源。CORS 不作为认证、资源授权或完整 CSRF 防护。
- 使用 Cookie 等浏览器自动携带的凭据时，落实适用的 CSRF 防护及 Cookie 的 Secure、HttpOnly、SameSite 等属性；方案结合实际跨域和登录流程确定，不只依赖 CORS 或 SameSite。状态变更采用对应写操作，不放入普通读取接口。
- 提供网页时复用框架输出转义；确需渲染不可信 HTML 时使用成熟清洗方案。CSP 等安全头按页面和资源需要配置，不对纯 API 机械叠加整套页面策略。
- 提供网页时，从 [实际生产托管入口](build-delivery.md#同进程静态托管) 验证浏览器功能和资源策略。第三方及 SDK 外部资源按生产必要性允许、限制或关闭，不仅为消除报错放宽策略。
- 正文限制在 JSON／SDK 解析前按实际读取字节执行，不仅依赖声明长度或解析后的大小。按 [关闭接入顺序](service-lifecycle.md#退出协调与资源顺序) 尽早拒绝新业务，拒绝后不继续业务解析、依赖调用或写入；框架必要排空保持有界。

### 输入、秘密与外部访问

- 输入类型和协议校验沿用 REST 契约，明确可修改和可返回字段；请求对象不整体绑定内部记录，内部对象不整体外返。用户、租户、角色等权限字段从可信身份与授权结果确定，业务需要选择这些目标时单独验证其范围。
- 管理密钥等秘密时默认写入不回显，读取模型按需返回配置状态，输入与读取模型分开。明确省略、空值、轮换和删除的语义，确需展示或导出时单独授权；普通查询缓存、浏览器持久化、AI 上下文及遥测不携带秘密，敏感响应按用途限制缓存。秘密输入、日志和错误处理仍复用所属模块。
- 命令执行优先使用对应 API 或参数数组，并校验命令、参数及可操作范围；文件路径和上传使用受控目录及服务端命名，限制大小和实际类型，不仅相信客户端文件名或 Content-Type。涉及不可信路径时核对规范化及适用的符号链接边界。
- 服务访问用户提供的 URL 时单独约束协议、目标、重定向及实际连接地址，防止绕过到云元数据、回环和未经允许的内网。优先使用预配置目标或允许范围，结合 DNS 解析和实际 HTTP 客户端验证，不能只检查初始 URL 文本；业务确需内部集成时明确允许范围。

### 资源限制与执行隔离

- 对适用请求体、上传、分页、批量数量、执行时间及并发设置明确上限。登录、公开接口、导出和模型调用等易滥用或高成本操作明确限流或配额，单次工作量也受控制；具体数值按工程确定。
- 退出、撤销、取消等控制操作采用明确的独立策略，按需使用独立配额、预留容量或其他有界方式，避免登录或普通业务额度耗尽后无法收回会话或停止自己的工作。认证、适用 CSRF 及动作对应的资源归属校验仍保留，不将控制入口变为无保护的旁路；关闭期间的可达范围由生命周期模块协调。
- 并发上限检查与预留在异步启动前原子完成，同资源重复执行按已确定业务契约拒绝、复用或允许并行，避免检查与启动之间无意突破限制。分别核算 HTTP／SSE 连接和后台执行容量，订阅断开、取消被接纳或停止失败均不证明后台执行结束；名额归属、启动失败及终态释放遵循 [生命周期的工作交接](service-lifecycle.md#后台工作与资源所有权)。
- 复用网关能力时核对实际生效，业务并发及操作成本由服务控制；多实例明确单实例与全局限制的区别。不默认增加 Redis 或通用限流框架，限制失败按 REST 约定表达。
- 工程执行脚本、外部工具或不可信代码时，明确文件读写、网络、环境变量、凭据、资源和输出限制，必要时采用操作系统或容器隔离。文件 API 的只读设置、工作目录和子进程隔离分别验证，设置 rootDir 不能作为隔离证据。
- 子进程按实际用途提供最少环境和凭据，不默认继承主服务全部秘密；确需访问某项资源时限定范围。执行超时、取消和清理复用调用与生命周期规则，只清理本次拥有的进程和资源。

### 安全事件与强审计

- 认证与授权拒绝、权限或凭据变更、重要管理操作记录必要主体、动作、资源、结果及关联标识，复用日志字段和脱敏机制。高频拒绝控制噪声，不能把秘密或完整请求作为审计内容。
- 强审计按合规或业务追责需要建立，明确持久化、防篡改、访问、保留期及审计失败是否阻止操作；数据库事务边界遵循数据库模块。默认不创建独立审计平台，普通日志和强审计的保证分别说明。

### 依赖、安装脚本与安全检查

- 新工程 CI 默认接入适用的依赖漏洞及秘密扫描，已有有效方式保留；镜像扫描优先复用 ECR 或团队现有能力，不固定扫描产品。CI 触发和执行接入构建交付模块，不建立绕过现有验证入口的第二套流程。
- 真实秘密泄露、未经例外批准且确认影响当前工程的高危或严重漏洞阻断交付。待确认项显式进入确认流程，不直接归为误报或标为通过；确需暂缓时记录影响、补救措施、负责人、批准依据与到期条件，不能静默放宽有效门槛。
- 扫描未执行、失败或工具不可用时明确状态和缺项，不显示为检查通过；被选为必需门槛的检查按测试模块的失败传播规则处理。保持检测报告和例外可追溯，报告本身也遵守秘密限制。
- 在实施早期执行授权范围内的基线扫描，保留工具／规则库、范围、时间、发现及实际输入身份；受影响版本、路径和产物不能因去重而丢失，报告不包含秘密原文。
- 报告来源须与实际输入及扫描对象可核对，覆盖缺失、来源不明或扫描失败不能算通过。镜像身份比较由 [交付模块](build-delivery.md#版本与交付记录) 维护，输入变化后按 [证据更新规则](testing.md#构建冒烟重试与结果) 重验。
- 扫描脏工作区时身份包含实际未提交及未跟踪输入，单一 HEAD SHA 不足；符号链接只扫描授权目标并声明覆盖。保留可追溯的原始扫描范围和快照依据，补写记录不能冒充新扫描，报告输出与输入区分；具体关联方式复用所选工具，不默认自建快照框架。
- 大量既有发现应明确本次治理范围、待确认项、修复或例外安排；不能直接忽略，也不因此默认开展全工程升级。分别报告实现完成、安全门槛通过或阻断及平台未验证，批准例外仍遵守上述负责人、依据与到期要求。
- 核对实际包管理器的安装脚本控制，必要脚本显式允许，新增允许项可追溯；没有对应机制时按实际工具链选择适用约束并说明边界。不统一禁止全部脚本，锁文件和漏洞扫描也不代替安装时执行代码的检查。

## 实施指引

1. 盘点实际入口、信任来源、敏感数据及外部依赖，依据当前暴露面选择适用控制，复用成熟身份与协议能力。
2. 接通当前范围内的保护和扫描门槛，明确需要外部平台落实的条件；没有相应业务的能力不预建，不扩展为成熟工程全面改造。
3. 长期规范记录公开例外、身份与撤权语义、限额和隔离、浏览器及外部访问策略、扫描门槛与批准例外，链接实际入口；遵循 [统一交付要求](../SKILL.md#统一交付要求)。

## 验收标准

按实际暴露面和本次修改选择下表，保留待验路由、中间件、SDK 或扫描器；策略函数单测不能代替真实接线。使用合成凭据、隔离资源及受控目标，扫描和探测限定授权范围。

### 重点场景与验证层级

| 范围 | 预期结果及验证方式 |
| --- | --- |
| 入口与身份 | 从实际受保护入口验证匿名、无效凭据、越权及身份篡改被拒绝且无未授权副作用；公开例外明确，正式环境旁路误启用或必需配置缺失时失败 |
| 登录、撤权及跨服务 | 适用协议事务与账号映射正确，停用、退出、缓存及轮换按声明生效；下游验证调用身份、用户权限和请求匹配，本地替身不证明身份提供方接通 |
| 浏览器与正文 | 实际浏览器及生产路由验证 CORS、CSRF、Cookie、输出和资源策略，伪造代理信息不能绕过控制；字节上限和拒绝顺序在真实中间件链生效，外部 TLS／网络另验 |
| 秘密及不可信输入 | 合成秘密不进入响应、日志、缓存或 AI／遥测输出；文件、命令、URL 的越界及重定向被拒绝，执行隔离和最少凭据实际生效 |
| 容量与控制操作 | 受控并发不超限，普通配额耗尽后必要控制仍按独立有界策略工作且保持授权；连接与执行分别核算，释放遵循生命周期契约 |
| 审计与供应链 | 实际扫描器能发现受控样例，来源和范围可追溯；缺来源、执行失败、待确认及批准／过期例外正确进入门槛，安装脚本许可与实际执行一致；强审计验证所选保证 |

区分应用、CI 及外部平台证据，不将未发现问题描述为全面安全。实施安全基础不授权生产变更、任意网络扫描或真实凭据使用。
