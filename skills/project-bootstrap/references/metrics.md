# 指标与可观测性

建立或补齐指标采集、基础与业务埋点、查询及面板，或接入链路追踪时读取。新建常驻后端默认采用 Prometheus 拉取指标，提供 `GET /metrics`；已有工程保留有效接入、路径和命名，明确实际覆盖范围。

## 适用条件与产出

适用于需要观察请求质量、资源或执行状态的服务与工作进程。库复用宿主的观测能力，静态前端不额外启动指标服务；短时任务按执行方式选择可用采集路径，不强制增加 HTTP 服务或默认引入 Pushgateway。

产出包括适用的采集入口、指标注册与埋点、实际指标目录、基础查询、必要的面板和部署接入说明，以及验证结果。复用现有客户端、框架和采集设施，不仅为满足形式重复埋点或部署一套监控平台。面板与告警按实际平台和服务目标接入，完整链路追踪按需采用。

## 采集入口与进程范围

- 新建常驻后端的基础指标默认随进程启用，有实际需求才增加开关，已有工程保留有效接入与启用策略。使用成熟客户端输出 Prometheus 支持的格式及对应 Content-Type；`GET /metrics` 提供采集数据，不套用业务 REST 响应包裹或错误码协议，已有有效路径保留。
- 指标入口按采集平台要求和实际网络边界确定访问范围及鉴权，不默认增加 Bearer 或其他固定认证方式，避免暴露凭据及敏感业务数据。平台目标发现、网络访问及身份标签由部署配置接通，项目特有的平台限制维护在长期规范中，生成配置不代表实际采集已完成。
- 每个实际进程或应用明确注册范围，优先使用显式 Registry 或框架等价隔离机制。复用已有注册器时核对初始化、测试隔离和生命周期；重复接入不重复注册或重复计数，不依靠忽略冲突宣称初始化成功。
- 多进程、组件及实例分别明确采集目标，保留必要身份维度。每次拉取应对应稳定的实际目标，不能通过随机转发到不同实例的负载均衡入口读取同一条进程 Counter。
- 服务、环境和实例身份优先由采集配置提供，应用与采集侧明确责任，避免重名冲突；Prometheus 的 `job`、`instance` 由抓取侧负责。应用任务使用 `job_name` 等不同标签，需要组件维度时采用稳定、有限取值。
- 采集入口保持轻量，避免同步执行昂贵业务查询或等待多个外部服务。确有自定义采集需求时明确超时、缓存和失败表达，不将查询失败伪装成正常零值。
- 指标记录故障默认不改变业务结果，提供有界的安全诊断；开始、完成及异常路径都要核对，不能让 recorder 的异常阻断业务或原有清理。诊断记录遵循 [日志模块](logging.md)。

### 注册器与采集器的关闭契约

注册器与采集器分别明确所有权，重复组装不重复注册或创建后台活动。按 [统一退出协调](service-lifecycle.md#退出协调与资源顺序) 在最后使用后释放，核对实际后台资源已停止，清空注册不等于关闭。共享资源不被单个使用者误关；拉取与关闭竞争时返回契约范围内的完整结果或明确不可采集，不把清空后的部分结果当作成功快照，也不要求所有数值原子采样。

## 最小指标与命名

新建 HTTP 服务采用以下团队默认名称及类型，已有工程保留有效命名、标签和语义映射。这些名称是团队约定，不宣称为 Prometheus 强制标准。

| 指标名 | 类型 | 语义 |
| --- | --- | --- |
| `http_server_requests_total` | Counter | 统计范围内已结束的请求数量，完成与取消等结果按真实结束语义表达 |
| `http_server_request_duration_seconds` | Histogram | 请求进入到响应完成或按契约结束的耗时，单位为秒 |
| `http_server_requests_in_flight` | Gauge | 当前正在处理的请求数量，结束时归还 |

- 进程 CPU、内存及适用语言运行时指标优先使用成熟采集器，保留其标准名称，不为符合应用名字重新实现采集或重复导出。
- 有后台任务时增加执行次数、耗时、正在执行数量及最近成功时间；有重要外部调用时按需增加调用结果与耗时。业务指标围绕实际观察问题添加，不预建尚未使用的领域指标。
- 指标与标签采用 `snake_case`。累计计数以 `_total` 结尾，耗时使用秒、容量使用字节等基础单位，并通过名称后缀和元信息明确单位；同一指标只表达一种量和单位。
- 通用基础指标使用统一名称，业务专属指标使用稳定的业务或模块前缀；不将动态值拼入指标名。实际目录记录名称、类型、单位、标签范围、执行入口、统计口径及重启行为。

### 标签与数量约束

- HTTP 计数及耗时默认使用 `method`、`route`、`status_code`。在途数量不带尚未确定的状态码，使用可可靠取得的有限请求维度；增加与归还使用同一组标签。
- `route` 使用实际路由模板，如 `/users/:id`，未知路由使用固定值。业务路由主动返回 404 仍保留自身模板，不仅根据状态码判断是否匹配；不得退回原始 URL、路径参数或查询字符串。
- SDK 内部 Router 无法提供细分模板时，可显式登记稳定的挂载模板，说明挂载级聚合范围及内部未知路径的可区分程度，不冒充已识别具体内部路由。挂载之外的未知路径使用固定分类，挂载内外的任意路径都不能生成动态标签。
- 方法、结果、任务名称及业务分类有明确、受控的取值范围，未知输入归入固定分类。请求、用户、会话等标识及错误文案不进入普通指标标签；有限枚举也要核对维度组合与 Histogram 桶带来的序列数量。
- 不为全部 REST 错误码或业务对象默认增加标签。确有分类分析需要时，选择稳定且受控的类别，详细关联诊断通过日志及适用追踪处理。

## 执行边界与统计口径

### HTTP 与外部调用

- 从实际入口按单调时钟计时，在服务器可观察的结束边界累计一次请求和耗时，并归还同组标签的在途数量。覆盖认证、解析、校验及未知路由等处理前失败；默认排除 `/metrics`、`/health`、`/ready`，已有排除和框架限制明确记录。
- handler 返回不等于正文结束。适用无正文、流、背压及取消场景使用真实完成事件，不因埋点预读正文而改变业务消费行为；不宣称测量客户端接收时间。资源排空遵循 [生命周期模块](service-lifecycle.md#退出协调与资源顺序)。
- HTTP 状态与业务结果分别表达：4xx 不一律为系统故障，已发送 200 不代表流或业务成功，未知状态不伪造。异步接纳与最终执行分别统计；首字节耗时、流内结果或连接数有需要时另设指标。
- 外部调用区分重试尝试与整次操作，数量、结果及耗时使用一致分母；复用已有埋点，重试与取消遵循 [错误处理模块](error-handling.md#超时取消与重试)。

### 后台任务与持久化边界

- 明确接纳、开始和结束边界；涉及事务时，接纳或持久化成功在相应提交完成后记录。整项业务、子项及协议阶段分别定义成功，部分失败或结构化错误不能因正常返回就记为全部成功。
- 按 [实际执行结束与所有权](service-lifecycle.md#后台工作与资源所有权) 幂等结束计时并归还在途数量；取消被接纳或停止失败时仍在执行的工作继续计数。实际执行结束后，补偿或清理失败也不能泄漏 Gauge，应保留失败诊断。
- Gauge 表示实际并发数，进程计数与持久化全局状态分别定义；Counter 不作为完整业务账本，恢复任务不为补统计而重复记录。
- 最近成功时间使用 Unix 秒。默认零表示本进程尚无成功记录，重启重置；初始化不计成功，禁用任务不生成执行序列。跨重启或全局统计从可靠来源获取并声明不同口径。

## 耗时分布与查询

- 耗时默认使用 Histogram。新工程核对客户端、采集端及查询平台的整条支持链，支持时优先采用原生 Histogram，否则使用经典 Histogram；已有有效实现保留。
- 经典桶边界依据实际延迟及服务目标确定，不统一固定桶列表。普通接口、长任务和外部调用分别配置适用范围；需要聚合的实例保持指标类型、单位、标签及经典桶边界兼容。
- 跨实例分位数从聚合后的分布计算，不平均各实例 P95。Counter 先计算 `rate` 等适用变化函数再聚合，避免掩盖实例重启；观察窗口与真实抓取周期和事件频率匹配，Gauge 不按 Counter 计算速率。
- 基础查询至少覆盖请求速率、5xx 比例、延迟分位数，以及适用任务的执行结果、在途数量和最近成功情况。查询使用目标工程实际指标、身份维度及采集格式；面板变量、数据源与标签插值按真实平台验证，不硬编码个人生产数据源。
- 区分零、无流量、任务禁用和采集缺失。首次失败前没有错误序列时，仅在对应总事件序列存在的前提下补错误零值；不把所有缺失统一显示为零，不把无流量时的无值或 NaN 当成失败率零。
- 比例和分位数告警依据适用样本量、观察窗口及持续时间确定；任务未成功告警结合调度周期、首次执行时间和重启宽限期。阈值及通知渠道按服务目标和实际平台选择，不固定跨工程数值。
- 采集失败与业务失败分别观察。Prometheus 的 `up` 是抓取侧目标指标，不默认带应用自行附加的全部标签；按实际目标标签查询。低频事件、首次抓取前事件及变化函数的估算限制写入查询说明，不能当作精确业务统计。

## 链路追踪

- 完整追踪按需接入，优先复用已有设施，明确实际采集内容、采样、导出目标和关闭刷新。依赖包含 OpenTelemetry 或框架支持追踪，不代表上下文传播、导出和平台接收已接通。
- 请求及任务关联、真实 `traceId`／`spanId` 与传播规则遵循 [日志模块](logging.md#请求与任务上下文)。核对框架自动埋点与手动埋点，避免重复 Span 或无意启用外部导出。
- 默认只选择必要、安全的属性，避免自动采集凭据、完整请求正文、Prompt 或业务对象；验证框架和 SDK 实际输出，不能仅凭脱敏配置宣称安全。采样后的追踪不代替完整指标计数。
- 追踪输出故障默认不改变业务结果，队列、等待及失败诊断保持有界；刷新和释放接入 [统一退出协调](service-lifecycle.md#退出协调与资源顺序)，不创建独立抢先退出流程。

## 实施指引

1. 检查已有采集、注册、埋点、查询和追踪，确定进程范围与最小接入；保留有效名称并记录映射。
2. 接通默认基础指标及所需业务指标，确定有限标签、执行口径和 Histogram，连接真实框架及统一退出。
3. 长期规范维护实际指标目录、启用与访问政策、统计口径、查询及缺失语义；按 [交付模块](build-delivery.md#外部部署交接) 说明采集前提，面板、告警与追踪按需求落实。

## 验收标准

遵循 [测试政策](testing.md#测试政策)，验证真实输出和接线；按修改范围选择下表，不为验收新增 SDK、流或监控平台。区分应用输出、生产产物及平台接通情况。

### 边界场景与验证层级

| 检查范围 | 预期结果及验证方式 |
| --- | --- |
| 基础采集与注册 | 从实际入口核对默认启用、格式、类型、单位、身份及访问范围；重复初始化无重复注册，进程数据隔离 |
| HTTP 埋点 | 经真实路由验证成功、处理前失败、业务 404 与未知路径，有限模板标签和排除范围有效；有打包依赖时从生产产物验证 |
| 完成与执行口径 | 适用流、取消及并发结束只计一次、在途归还且不为负；任务提交、结构化失败、部分成功及重启语义符合上述契约，保留实际 SDK 转换路径 |
| 故障与关闭 | 记录故障不改变业务或阻断清理；实际采集器在最后使用后释放，关闭竞争不输出部分成功快照，共享资源不误关 |
| 查询与平台 | 具备环境时确认各实例持续被采集，验证聚合、重启、Histogram 支持及零值／无流量／禁用／采集缺失；面板与告警验证实际数据源、变量和表达式 |
| 按需追踪 | 从实际请求验证传播、采样、导出及退出刷新，合成秘密不进入实际属性；应用验证不能替代平台接收证据 |

采集、面板、告警或追踪缺少外部条件时分别报告未验证范围；本模块验收不触发生产变更或真实通知。
