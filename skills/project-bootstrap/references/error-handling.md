# 错误处理与 REST 接口约定

建立或补齐错误分类、全局错误码、REST 请求校验与响应、超时及重试策略时读取。统一错误语义、稳定标识和安全要求，具体响应格式由 Agent 与使用者商定，已有工程沿用有效协议。

## 适用条件与产出

适用于提供 REST 接口的工程及其业务与外部依赖调用。没有 REST 接口时，仅按实际需求采用内部错误处理和调用策略，不因此增加 HTTP 入口或 REST 错误码体系。MCP、gRPC 等专门协议另行维护，本模块不定义其响应、错误登记或跨协议映射。

产出包括工程内的全局错误码登记与命名空间规则、错误传播与 REST 转换入口、请求与响应契约、适用调用策略、长期错误处理规范和实际验证结果。复用已有异常体系、校验器、中间件及接口文档，按差异补齐。

## 错误语义与传播

- 按调用方需要采取的行动区分输入不合法、业务条件不满足、外部依赖失败和未预期的内部错误。认证、授权、资源不存在、冲突、限流等按实际需求细分，不预建完整错误目录或每类一个异常类。
- 内部表达沿用语言和框架惯例，异常、错误返回值或结果类型均可；同一调用链保持一致。业务逻辑表达业务失败，由 REST 入口转换为响应，不要求业务模块依赖 HTTP 框架。
- 工程自己产生的错误通过类型或稳定标识识别，内部和外部调用方都不依赖提示文案分类。第三方仅提供非结构化诊断时，将必要解析限制在接入位置，并对无法识别的情况安全兜底。
- 在能够恢复、补充必要上下文或转换对外表达的位置捕获错误。传播保留可供内部诊断的原始原因，避免逐层机械包装、吞掉失败或返回假成功；保留原因不代表向客户端或日志输出完整错误对象。
- 捕获范围与转换依据应对应可识别的失败来源，区分传输失败、上游协议失败和本地解析或编程错误；不能把一次调用周围的所有异常都转换为依赖故障。未知异常保留原因并交已有安全兜底，不依据异常出现的位置推定来源。
- 错误转换同时约束状态副作用：清会话、清 Cookie、撤权、清缓存或返回空结果等动作必须有匹配的可信失败语义及项目契约。依赖查询故障不能被当作会话失效或权限撤销，失败不能被转换为正常空结果；需要降级时明确其失败表达。
- 业务明确允许时可以降级或返回部分结果，需定义剩余结果是否可用、失败如何体现及整体失败条件。按契约保留失败标记、各项状态或适用的内部观测信息，查询失败不能被误认为正常的“没有数据”。

## 全局错误码登记与命名空间

- REST 对外需要稳定识别的应用错误统一登记，采用“全局登记、按命名空间分配、模块负责语义”。错误码在单个工程内全局唯一，不要求跨工程唯一；内部异常和 SDK 错误按需映射，不全部分配公开标识。
- 新工程默认数字号段；已有数字或字符串错误码沿用有效形式，分别按号段或字符串前缀管理命名空间，不额外建立双重编号或别名登记。具体范围、前缀、类型与存储方式适配工程，模块负责所属错误的语义、定义和使用。
- 登记是唯一事实来源，可集中存储，也可按模块维护后自动汇总。至少可查错误码、名称、含义、所属模块、使用状态及对应 HTTP 状态；记录通用与模块命名空间的范围或前缀及归属，新增模块从未分配空间领取。从定义生成总览或文档，避免维护两份独立清单。
- 用项目现有工具或轻量检查验证错误码唯一、命名空间归属明确、数字号段无重叠、错误未越界或违反前缀规则，以及响应所需元信息完整。分配命名空间不能代替重复检查，重复、归属冲突或缺项应使检查失败。
- 已发布错误码不改变含义、不回收复用，废弃后保留登记。提示文案可以改善，兼容性以稳定标识及语义为准；接入已有工程时不为统一样式重新编号或改类型。
- 业务错误码与 HTTP 状态分别表达各自语义；客户端使用稳定错误码识别具体失败。未知内部异常使用安全的通用错误码，不为每个底层异常新增公开标识。
- 服务端自己的公开错误受登记与元信息检查约束；客户端对结构合法但尚不认识的错误码保留安全兜底，不因封闭枚举或未知值而崩溃。未知值不能直接推定为会话失效、权限变化或允许自动重试；结构非法则按本地协议解析失败处理，两者分别验证。

## REST 契约与请求链路

### 商定项目表达

先检查已有响应、认证中间件、错误转换、接口文档及客户端使用方式。新工程由 Agent 提出具体方案，与使用者商定成功与失败结构、错误码及安全提示的位置、必要的校验细节；已确认的选择直接沿用，不重复询问。

RFC 9457 的 Problem Details 可作为错误响应选项，也可使用项目认可的结构；不预置统一包裹所有成功响应的要求。已有工程保持有效协议，确需改变公开结构、状态或错误语义时说明调用方影响，按认可的兼容方案处理。

### 校验与转换

- 在外部输入进入业务逻辑前校验类型、格式及协议约束，业务状态和业务条件由所属模块判断。复用同一份约束定义，保留必要的数据库等最终约束，不在 handler 重复执行框架已完成的校验。
- 明确未知字段、类型转换、空值及缺失值的处理，与认证和请求解析中间件的实际行为一致。分页、时间格式、URL 与版本策略等仅在当前接口需要时确定，不预置整套 API 风格。
- 同一 REST 接口体系采用一致的错误转换和安全兜底，HTTP 状态符合已确定的失败语义。已有框架认证等响应存在兼容差异时明确记录适用范围，不用局部业务响应的统一代替完整链路验收。
- 覆盖请求解析、认证、参数校验、业务拒绝、未知路由和未捕获异常的处理位置。复用框架提供的扩展入口，避免让非法 JSON 或未知异常意外返回破坏契约的响应。
- 接口文档描述实际输入、成功与失败响应及适用错误码，与真实中间件行为一致。文档或契约文件沿用现有工具，不只声明成功响应，也不把 HTTP schema 的全部细节复制进领域模块。

## 对外信息与内部诊断

- 对外提示仅包含安全可公开的原因。未知异常返回通用提示，不直接转发堆栈、SQL、秘密、连接信息、原始请求或第三方响应正文。
- 按实际排障需要允许字段路径、失败阶段、限制值和处理建议等诊断信息，明确可公开字段、脱敏及长度限制。任意异常 message 不自动成为安全提示；无法确认时使用通用提示。
- 保留原始原因供内部排查，并在已有机制支持时关联请求标识。日志级别、字段、堆栈及重复记录策略由 [日志模块](logging.md) 维护；本模块不额外建立日志体系，也不为诊断读取或复制真实秘密。

## 超时、取消与重试

- 外部调用有明确的超时策略，区分连接、等待响应头、正文读取和整次操作预算，说明起止边界与组合关系；预算覆盖正文时，收到响应头不能提前解除。先核对 SDK 和框架已有超时、重试及取消行为，再补充缺项；具体时长按项目需求和运行条件确定。
- 超时与主动取消竞争时，保留首先发生且能可靠确认的原因，涵盖调用前已取消的信号。不能仅在最终捕获时查看哪个信号已触发来重新分类，迟到信号不覆盖原有归属；无法可靠判断时明确诊断边界，不伪造原因。
- 支持取消时将调用方取消与超时信号传至下游，所有结束路径清理本次创建的计时器、监听器、正文和流等资源。失败响应正文也按客户端契约受控读取、释放或取消，不因已取得错误状态就遗留资源。仅停止等待不能算下游已停止；依赖不支持取消时说明残留工作、资源与副作用风险。
- 主动取消不默认归类为内部故障，也不自动重试。超时表示等待预算耗尽，涉及写入时结果可能未知，不能据此声称未生效或已回滚。
- 不统一开启自动重试。启用前明确可重试失败、操作幂等保障、负责层、尝试次数及包含执行和等待的总耗时限制，盘点浏览器请求层、业务 Client、SDK 的实际策略及叠加次数。采用有上限的退避，必要时加入随机抖动；取消或预算耗尽后停止重试，客户端不能自动重试业务拒绝、本地解析失败或取消。
- 写入结果未知时，客户端提示及交互引导查询或核对最新状态，不直接展示确定失败或默认再次提交；再次执行须符合工程的幂等与恢复契约，不能只在后端文档写禁止重试而保留无条件重发的页面动作。
- 熔断、复杂降级、自动补偿及幂等键机制按实际需求设计，不作为每个工程的初始化必选项。需要配置的策略复用 [配置模块](configuration.md) 的加载与校验规则。

### 共享异步工作的取消与恢复

仅在存在多等待者共享工作时，明确底层所有者、等待者预算和取消范围；单个等待者退出不越权取消他人工作，请求信号不污染共享 SDK。暂时失败可按策略恢复，永久失败明确恢复条件，遵守总预算；实际结束和迟到资源按 [生命周期规则](service-lifecycle.md#后台工作与资源所有权) 处理，不默认建设共享任务框架。

## 实施指引

1. 检查现有错误登记、传播、REST 及客户端契约，商定尚未确定的表达和兼容选择，保留有效协议。
2. 接通全局登记与检查、安全转换和输入校验，只补齐实际需要的超时、重试及共享工作策略；认证授权仍由 [安全模块](security.md) 负责。
3. 长期规范记录错误语义、命名空间、转换副作用及调用策略，链接唯一登记、协议与验证入口。总览或文档生成遵循 [命令产出要求](testing.md#查询与生成命令的产出)。

## 验收标准

遵循 [测试政策](testing.md#测试政策)，按实际范围验证，故障注入使用隔离依赖与合成数据，不制造真实副作用。

- 全局登记可查询，重复、归属冲突、越界或缺元信息时检查失败，已发布语义保持兼容；客户端安全处理合法未知码，非法结构按解析失败处理，不擅自清会话或重试。
- 经真实 REST 路由及中间件验证成功、解析／认证／校验失败、业务拒绝、未知路由与异常，响应和文档一致。分类基于可识别来源，副作用符合契约，依赖故障不冒充无数据或会话失效。
- 失败响应不泄露内部信息，安全诊断仍能定位原因；部分成功或降级真实反映未完成范围。
- 本次涉及调用策略时，验证预算覆盖声明的执行与正文范围、取消传递及清理，原因不被迟到事件覆盖。经真实调用层核对重试次数和总预算，结果未知时客户端引导核对而非无条件重发。
- 存在共享工作时验证等待者独立退出与失败恢复，未结束底层工作按所有权处理。替身只证明声明范围，真实外部接入未验证时明确说明。
