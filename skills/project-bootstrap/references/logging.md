# 日志与请求上下文

建立或补齐日志入口、字段、级别与错误记录，或调整日志实例所有权、异步回调绑定、SDK 日志接线及请求和任务上下文时读取。让维护者通过必要事件和关联标识追溯执行过程，具体日志库和上下文机制适配技术栈。

## 适用条件与产出

适用于需要运行日志的服务、应用、命令行工具及后台任务。库复用宿主提供的日志能力，不强制配置全局输出；没有请求入口的工程跳过 HTTP 上下文，不因此增加服务或追踪平台。

产出包括统一日志入口、配置与实例所有权、字段及事件约定、适用的请求或任务关联、回调与 SDK 接线、完成摘要、错误与敏感信息处理，以及实际输出和行为验证结果。已有工程保留有效字段、格式和采集方式，记录与本模块语义的对应关系；仅补齐实际缺项，不整体改写现有日志。

## 输出与统一入口

- 服务生产环境默认向标准输出写结构化 JSON，由运行平台采集；命令行工具有机器可读输出时，日志使用标准错误等独立通道。文件、轮转和其他输出目标按实际部署需要选择。
- 开发环境允许可读展示，基于同一份结构化记录，不另行定义字段或改变语义。检查框架、日志库及采集器的实际输出，不能只凭配置认定格式已接通。
- 业务代码通过统一入口记录，核心字段及当前执行的关联标识由日志入口补充。复用现有配置与扩展机制，避免各模块创建独立配置或重复输出同一记录。
- 日志级别、输出与脱敏配置遵循 [配置模块](configuration.md) 的加载、校验及生效约定。新工程生产默认级别为 `info`，`debug` 和 `trace` 默认关闭；已有明确约定时沿用。

### 根日志实例（Root）的所有权

- Root 有明确初始化入口、资源所有者与关闭责任，子 Logger 或 SDK 适配器不自动获得关闭权；库复用宿主能力，不强制进程单例。
- 模块导入不隐式创建需关闭资源。初始化失败回收已获得资源，关闭幂等；不支持的初始化或调用顺序明确拒绝。实际支持并发初始化、重建或多实例时，保证旧句柄不会影响新实例。
- 关闭接入 [统一退出协调](service-lifecycle.md#退出协调与资源顺序)，沿用其依赖顺序和总预算。

### 输出写入者与记录边界

- 清点应用 Logger、已适配 SDK Logger、第三方直接输出及其实际通道，分别说明结构化、脱敏、限长和刷新保护的覆盖范围；第三方绕过统一入口时，不能把应用 Logger 的保证推广到整条通道。
- 同一通道有多个写入者时，在声明支持的记录大小、缓冲与积压范围内保持记录边界和末尾完整性。按实际能力统一写入或隔离通道；无法保证的部分明确记录，不仅因单一 Logger 输出正常就认定共用通道已验证。

## 字段与类型

### 核心字段

新工程自身产生的每条结构化日志包含以下字段。已有工程保留有效名字、类型及级别表示，在日志说明中记录映射；框架或第三方日志按可配置能力接入，未覆盖的部分如实说明。

| 字段 | 类型 | 含义与约定 |
| --- | --- | --- |
| `timestamp` | 字符串 | 日志产生时间，UTC、ISO 8601 格式，保留毫秒，例如 `2026-10-14T08:30:00.123Z` |
| `level` | 字符串枚举 | `trace`、`debug`、`info`、`warn`、`error`、`fatal`；按日志库能力映射，记录中采用对应语义 |
| `service` | 字符串 | 稳定的应用或服务名称，不包含实例编号 |
| `environment` | 字符串 | 配置确定的运行环境，例如 `development`、`test`、`production` |
| `message` | 字符串 | 简短、面向人的描述，默认中文；机器识别事件使用适用的稳定标识 |

### 场景字段

字段按下表的条件添加；不适用时省略，不填空字符串或虚构上下文。

| 字段 | 类型 | 使用条件与约定 |
| --- | --- | --- |
| `event` | 字符串 | 需要稳定检索或统计的事件名，例如 `http.request.completed`；动态 ID 放独立字段 |
| `component` | 字符串 | 需要定位模块时填写稳定模块名 |
| `requestId` | 字符串 | 请求处理及由该请求触发的相关业务日志的关联标识 |
| `executionId` | 字符串 | 后台任务或独立操作每次执行的标识，不同执行使用不同值 |
| `traceId`、`spanId` | 字符串 | 已有真实追踪上下文时填写，遵循追踪系统格式；有 `spanId` 时同时关联 `traceId` |
| `durationMs` | 数字 | 操作耗时，毫秒，非负有限值；用单调时钟计算，明确起止位置 |
| `errorCode` | 整数或字符串，按工程确定 | 存在已登记的 REST 应用错误码时填写，沿用工程登记及协议的稳定类型，不按事件任意转换或另建编号，定义由 [错误处理模块](error-handling.md#全局错误码登记与命名空间) 维护 |
| `error` | 对象 | 需要异常诊断时，包含安全处理后的 `type`、`message` 及适用的 `stack`，这些子字段均为字符串 |
| `method` | 字符串 | HTTP 方法，例如 `GET`、`POST` |
| `route` | 字符串 | 匹配的路由模板，不使用带动态 ID 或查询串的完整 URL；未知路由使用固定值 |
| `statusCode` | 整数 | HTTP 最终响应状态 |
| `outcome` | 字符串枚举 | 需要表达操作结果时使用 `success`、`failure`、`cancelled`、`timeout`、`partial`，与事件的实际结果一致 |

业务日志只添加当前事件需要的业务字段，例如条目数量、目标语言及匹配数量；由请求触发时继承 `requestId`，由任务触发时携带 `executionId`，独立执行且无关联上下文时省略二者。业务日志无需附带 HTTP 方法、路由与状态。

业务扩展字段不能覆盖核心字段或当前执行的关联标识，也不能改变已确定的字段类型。核对日志库绑定字段与单次调用字段的合并行为，避免重复键或调用参数覆盖入口生成的标识。

## 日志级别与记录位置

| 级别 | 用途与默认选择 |
| --- | --- |
| `trace` | 高频、细粒度执行细节，默认关闭 |
| `debug` | 排障细节、重试过程及关键分支，生产默认关闭 |
| `info` | 启停、请求或任务完成、重要业务事件及正常业务拒绝 |
| `warn` | 已恢复的异常、降级及接近资源限制等需要关注但仍可继续的情况 |
| `error` | 非预期异常，或依赖故障导致操作无法完成 |
| `fatal` | 应用无法继续运行的致命故障；退出由生命周期机制负责，核对日志调用自身的副作用 |

- 按事件影响选择级别，参数错误、资源不存在及业务条件不满足等正常拒绝不一律记为系统错误。主动取消通常使用 `info`；超时按实际影响选择，不能仅凭异常类型或 HTTP 状态决定全部业务日志的级别。
- 重试过程默认使用 `debug`，最终失败由负责处理结果的位置记录。重要恢复或降级使用适用摘要，不让每次尝试都产生一条同义错误记录。
- 主要诊断由最终处理失败或决定降级的位置记录；其他层传播错误及必要上下文，不逐层重复同一堆栈。请求完成摘要与错误诊断可分别存在，摘要记录结果、耗时和标识，不再次复制完整异常。

## 请求完成摘要与取消竞态

- 默认为每个请求记录一次完成摘要，包含适用的标识、方法、路由模板、状态、结果及耗时；复用已有完成日志。健康检查等高频入口可明确排除或采样。
- 摘要依据服务器可观察的实际结束边界，覆盖无正文及适用流式响应；响应开始或 handler 返回不能代替正文结束。完成、取消与异常竞争时只记录一次，迟到事件不改写终态。
- `statusCode` 表达已确定的 HTTP 状态，未知时省略；`outcome` 表达所记录操作的实际结果，已发送状态不代表业务成功。HTTP 与独立后台执行分别记录，执行边界遵循 [生命周期模块](service-lifecycle.md#后台工作与资源所有权)，与 [指标口径](metrics.md#http-与外部调用) 一致。

## 错误诊断与敏感信息

安全事件和强审计的适用要求维护在 [安全模块](security.md#安全事件与强审计)，本模块提供记录、关联和输出机制。

- 已知业务拒绝通常记录错误码、必要业务字段及结果，无须堆栈。非预期内部异常按需保留安全处理后的类型、消息与堆栈；需要原因链时按工程约定固定结构，限制深度与长度并处理循环。
- 执行与清理同时失败时，最终输出保留各自可定位的安全类型、阶段及原因。聚合错误和原因链按实际结构展开，限制数量、深度和长度并处理循环，截断注明省略；无法安全提取时使用安全摘要，不输出原始 SQL、参数或凭据。
- 优先选取必要字段，再对已知敏感路径脱敏。默认记录执行元数据，不直接序列化整个请求、响应、身份或 SDK 对象；请求与响应正文按明确需要筛选、脱敏及限长。
- 秘密、认证头、Cookie、连接凭据等不进入日志。嵌套对象及异常消息、堆栈和原因链也需处理，顶层字段脱敏不能代替这些检查；无法安全提取时使用固定安全摘要。
- `debug` 和 `trace` 遵守同样的信息限制。脱敏与输出上限作用于实际写出的记录，不能只依赖可读展示隐藏字段，也不使用真实秘密制作验证样例。
- 本模块维护日志字段、级别、诊断序列化和重复记录要求；错误分类与对外 REST 表达由错误处理模块维护，不改变其公开错误语义。

## 请求与任务上下文

- 目前默认由服务端生成 `requestId`，普通客户端的同名请求头不直接采用。只有项目已明确可信上游与接收规则时，才在格式及长度校验后复用上游标识；标识只用于关联，不作为身份或授权依据。
- 在认证、解析及校验前尽早建立上下文，通过 `X-Request-Id` 响应头返回标识，覆盖业务成功与失败。核对框架实际中间件顺序及扩展入口，业务 handler 内生成标识不能算完整链路已接通。
- 进程内优先使用框架或语言支持的执行上下文，也允许显式参数传递。日志入口自动补充必要关联字段，验证异步和并发隔离，不以共享可变变量保存当前请求。
- 上下文仅包含必要标识和安全元数据。业务需要身份时使用认证得到的可信信息，不从业务参数建立日志身份，也不自动将所有身份字段加入每条日志。
- 后台任务每次运行建立独立 `executionId`。请求派生的后台执行可保留来源 `requestId`，但建立独立执行上下文，不持有整个请求对象或沿用已结束请求的生命周期；请求取消与后台任务是否停止按明确的执行契约处理。
- 对支持约定的内部服务传播请求标识，第三方调用按其接口要求处理。已有追踪设施时通过标准机制传递真实追踪上下文，校验输入并明确可信与外部传播范围；不从请求标识伪造追踪标识。追踪接入及验收由 [指标与可观测性模块](metrics.md#链路追踪) 维护，不默认部署追踪平台。

### 作用域恢复与回调绑定

使用执行上下文时，嵌套调用及异常后恢复外层状态，可信身份补充不污染其他执行。实际需要绑定回调时，明确绑定时快照与执行时上下文的选择；跨作用域和并发调用保持身份、可变状态隔离及原调用语义，不延长整个请求的生命周期。

### 共享 SDK 的上下文归属

共享客户端或 SDK 不缓存某次请求的身份或 Logger 供后续执行复用；按当前执行或显式绑定的工作取得上下文。接入现有回调、克隆或日志适配时，沿真实 SDK 路径验证归属，不能只验证上下文工具函数。不为普通日志接入建立通用回调绑定框架。

## 输出故障与生命周期

- 普通日志故障不改变业务结果或阻断必要清理；强制审计按 [安全模块](security.md#安全事件与强审计) 确定失败策略。同步与异步故障均纳入处理，原始与清理错误分别保留。
- 故障诊断有界、脱敏且不递归依赖已失败的输出路径；无法送达时如实说明。异步输出明确缓冲上限、积压及丢弃策略，采样日志不作为完整事件计数。
- 正常退出前完成有界刷新和关闭，沿用统一退出流程，验证实际末尾输出；强制终止下的保证按实际能力声明。
- 采集、保留、检索权限及轮转沿用已有基础设施，不默认创建日志或审计平台。

## 实施指引

1. 检查已有日志及实际输出，确定字段映射、资源所有权和第三方通道覆盖，复用有效接入。
2. 接通统一记录、请求及任务关联、敏感信息处理和退出刷新；只在工程实际使用相应 SDK 或回调时适配其传播路径。
3. 长期规范记录字段与级别、事件和错误记录责任、上下文边界、输出与故障策略，链接配置及验证入口，遵循 [统一交付要求](../SKILL.md#统一交付要求)。

## 验收标准

遵循 [测试政策](testing.md#测试政策)，使用隔离输出和合成数据；按本次改动选择下述检查，分别报告应用、第三方通道与外部采集的证据范围。

### Root 与输出边界

- 捕获并解析实际记录，核对字段类型、映射、扩展字段保护及记录完整性；多写入者适用时验证共享通道和缓冲边界，注明未覆盖通道。
- 新增或修改资源管理时，验证初始化失败回收、关闭及实际支持的复用方式，旧句柄不能误关新资源；不为验收增加重建能力。

### 级别、错误与上下文

- 通过实际入口核对成功、业务拒绝及异常的关联标识、级别和记录责任，覆盖发生在业务处理前的失败。并发请求与后台任务不串用身份，适用 SDK 接线保留真实路径。
- 用合成秘密及聚合错误检查最终输出：必要诊断可定位，嵌套原因、循环及截断不泄密，执行与清理错误均被保留。

### 完成摘要与退出输出

- 请求完成、取消与异常产生符合契约的一次摘要；适用流式响应与独立后台执行分别核对实际结束，日志与指标口径一致。
- 首次实际工作后检查末尾输出及资源关闭；新增或修改故障处理时验证输出与清理同时失败，剩余清理仍推进、诊断不递归、等待有界。方法调用或 mock 通过不作为输出送达证据。
