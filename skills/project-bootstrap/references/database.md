# 数据库与 SQL

建立或补齐关系型数据库访问、表结构、SQL 脚本与独立初始化，或调整事务、关联维护及查询时读取。采用 `sql/` 脚本加 DBA 执行的团队默认，主程序启动不建表，不使用外键，由业务侧保证关联关系。

## 适用条件与产出

适用于使用关系型数据库的工程。先区分应用自有数据、外部业务数据源和框架管理的表，明确读写及 Schema 所有权。只读访问外部库时，仅接入实际访问能力，不生成或修改对方 Schema；没有数据库需求时跳过，不预建业务表或数据库框架。

产出包括实际需要的连接与访问入口、表结构及约束、版本管理中的 SQL 脚本、独立初始化命令、工程长期数据库规范，以及实际验证结果。复用已有驱动、ORM 或查询构建器，不预先固定数据库产品，也不为统一形式额外增加通用 Repository 层。已有工程保留有效结构及约定，不整体迁移命名或类型。

## Schema 脚本与独立初始化

- 应用自有 Schema 变更放在工程根 `sql/` 并纳入版本管理。新工程沿用 `YYYYMMDD-描述.sql`，同日多个脚本有依赖时增加可排序序号；已有数字或日期前缀沿用，执行顺序必须确定且可验证。扩展等前置操作明确排在使用它们的脚本之前。
- 生产增量由 DBA 在对应应用发布前执行新增脚本，记录执行范围及结果。主程序启动不建表或自动修改 Schema；本地及 CI 使用独立初始化入口，不连带启动 HTTP、Agent、后台任务或业务服务。
- 本地 Schema 首次初始化面向空库，与已有库升级及种子数据首次引导区分，安全重跑不要求所有表仍为空。明确初始化包含的脚本及前提，普通入口不混入重置、一次性回填或破坏性操作；按目录组织或显式文件清单选择，不能仅凭所有文件都在 `sql/` 就无差别执行。
- 修改前核对 SQL 基线的实际使用范围及兼容承诺：未上线、未在共享环境投入使用且仍可调整的首版基线，允许直接修改原始 SQL；已在共享或生产环境投入使用的历史脚本冻结，后续调整新增增量脚本。文件已提交或仅在隔离本地执行不构成冻结依据；状态不明时先核对使用事实，不无依据地追加 DDL。执行记录沿用 DBA 交付流程，不默认引入 Migration Framework、Migration History 或 Checksum 表。
- 框架自带的建表行为也要检查，优先迁到独立初始化阶段。确实无法分离时说明不满足的范围并明确讨论，不把框架行为默认为启动不建表的例外。
- 生成部署交付用 SQL 不等于获得生产执行授权。本模块在隔离本地或测试库验收，生产执行按 DBA 流程处理。

### 脚本、表与字段注释

- 每个 SQL 脚本有中文说明，记录变更目的、执行前提及顺序，以及适用的重复执行和失败恢复方式；复杂或容易误判的操作就近说明原因，不逐行复述 SQL 语法。
- 应用自有表和字段都有中文注释。表注释说明职责与存储对象，字段注释说明业务含义，并按需补充单位、状态值、缺失语义及业务关联；不只重复表名或字段名。
- 数据库支持时使用原生表与字段注释，让说明进入数据库元数据；不支持时在脚本中保留完整说明并记录限制。修改字段或表的含义时同步更新注释，按上述基线状态选择直接调整首版或新增脚本，不改写已冻结历史。

### 重复执行与失败恢复

| 脚本行为 | 要求 |
| --- | --- |
| 建表、加列、加索引 | 数据库支持时可安全重复执行，并核对最终结构；已有定义不符时报告差异，存在性判断不能证明结构正确 |
| 数据回填、转换 | 明确范围、批次、重复执行或中断恢复方式，避免无依据地全部归为一次性操作 |
| 删列、改名、删除数据 | 写明前提、影响、发布顺序与恢复方式，由 DBA 按计划执行 |
| 需要在事务外执行的操作 | 显式说明，实际需要时让执行入口支持；不默认给所有文件包同一种事务 |

- 按数据库与操作类型确定事务边界；MySQL DDL 隐式提交、PostgreSQL 并发建索引等限制需按目标版本核对，不承诺跨数据库统一回滚能力。
- 任一脚本失败立即停止后续执行，报告失败文件、已完成范围及可能已提交的部分，关闭或释放资源并返回非零状态。记录如何核对现状及继续修复，不用跳过错误掩盖失败。
- 回滚或清理失败不能遮蔽原始错误，最终输出遵循 [日志模块的聚合错误诊断](logging.md#错误诊断与敏感信息)。只有验证对应范围确已回滚，才报告回滚成功；独立文件提交后，后续失败不代表整次初始化已经撤销。
- 必要种子数据可通过专属脚本在建表后接入独立初始化，不强制另建 seed 工具。参数通过明确入口提供，不提交秘密；重复执行保留已有有效数据，不重新授权或覆盖用户修改。
- 明确种子首次引导及并发判定，重跑保留用户修改、停用与撤权状态，参数变化不隐式重新授权。恢复采用独立操作，按业务唯一性防止重复创建或归属错配，不默认建立锁表。

## 表结构与应用类型

新工程采用以下默认值，已有工程沿用有效约定。SQL 语法、字符集、类型及驱动机制适配目标数据库。

| 事项 | 默认值与调整条件 |
| --- | --- |
| 命名 | 表名使用单数，表和列使用 `snake_case`；唯一索引采用 `uk_<表名>_<业务含义>`、普通索引采用 `idx_`，已有有效命名保留 |
| 主键 | 每张表有明确主键，默认使用自增整数 `id`；数据已有唯一、非空且稳定的业务标识时，可直接以该标识为主键，无须额外增加自增字段 |
| 可空性 | 默认非空，允许空值时明确业务含义；不用虚假 ID、日期或没有业务意义的特殊值掩盖缺失 |
| 时间 | 表示时间点的字段保持正确时间语义，统一按 UTC 处理；日期等其他语义单独选型。`created_at`、`updated_at` 按需添加 |
| 文本与枚举 | 类型及长度表达实际数据与业务上限，不统一强制 `text`、`VARCHAR(255)` 或数据库原生枚举 |
| 删除 | 不统一增加软删除字段，按历史保留、恢复与业务唯一性需求选择物理删除、状态变化或其他明确机制 |
| 默认值 | 仅使用有明确业务含义的值，避免漏传参数被悄悄变成有效数据 |

- 主键、大整数、精确小数、时间和 JSON 一起确定数据库类型、驱动返回值、模块内部类型及适用的接口表示，验证边界值。不能因默认整数主键就把任意大整数或精确小数转成普通数字。
- MySQL 默认自增主键使用 `INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY`，其他数据库适配其整数类型、自增机制及范围。需要更大容量时依据实际需求明确调整，不默认换成大整数；已有有效主键保留。
- UUID 等明确业务标识可直接作为主键，类型根据标识及数据库选择，不限定为字符串，也不限定为分布式场景。主键已保证唯一性，无须给相同字段重复建立唯一索引。
- 关联表表达业务关系，与是否使用外键无关，同样按上述规则选择主键；需要防止重复关联时，关联字段组合另设 `uk_` 唯一索引。复合主键不作为新工程关联表的默认选择。
- 时间点的 UTC 与精度约定覆盖数据库会话、默认函数和驱动转换；通过实际读写及连接复用验证，不只检查配置。日期等其他语义单独处理，更新时间由一个明确位置维护，`updated_at` 不作为完整业务历史。
- 为业务标识明确大小写、空白及字符集语义，使规范化、比较、查询和唯一约束一致。需要保持外部原值的标识不擅自转换；人类文本与机器标识不机械采用相同排序规则。
- 字段长度及完整唯一索引符合实际数据库限制，不能用前缀唯一索引替代完整业务唯一性。已有数据需要转换比较规则时检查冲突及兼容影响，不仅修改 DDL 声明。

## 无外键关联、事务与并发

- 新建或调整表结构不新增外键，由业务模块承担关联完整性；已有外键的去除属于单独的兼容变更，不因执行本模块自动删除。数据库仍用主键、非空、唯一及适用的检查约束提供最终数据保障，索引用于支撑实际访问。
- 创建关联时验证关联对象存在及适用状态，删除、归档或停用对象时定义关联处理责任及历史保留方式。说明允许保留的历史引用，区分有意保留与无效关联。
- 并发下按实际关系采用必要的锁、条件更新、版本控制或其他协调机制，使关联创建和对象删除等路径遵循同一约定。单独的“查询存在后插入”或事务包装不能自动证明不会产生悬空关联。
- 事务围绕当前一致性要求划定，相关操作使用同一事务连接；提交、回滚及释放责任明确，失败不会误报成功。尽量将远程调用放在事务外，避免长事务等待无关工作。
- 并发冲突按业务语义处理，不默认提升全工程隔离级别或无限重试。仅对已识别且符合当前数据库、事务及副作用条件的冲突，有界重跑整个适用事务范围，并遵守 [错误处理模块的调用策略](error-handling.md#超时取消与重试)；超时、断连或提交结果未知不直接作为重试依据，先核对实际结果及安全恢复条件。
- 存在强制业务审计时，业务变更与同库审计记录在同一事务中提交；跨库或外部系统的审计单独设计，不承诺本地事务能保证原子性。不默认创建审计表或通用审计系统。

## SQL 访问、索引与连接

- SQL 收敛到职责明确的访问位置，通过模块接口提供行为，并转换驱动返回结构；框架惯用的小型 CRUD 可以沿用，不强制建立额外层次。
- 外部值使用参数化查询，动态表名、列名和排序选项通过明确允许名单选择。批量 SQL 的占位符与参数对应正确，不因使用 ORM 或查询构建器而跳过对实际生成 SQL 的检查。
- 常规查询选择实际需要的字段并限制结果；分页需要稳定排序，导出及批处理按需采用分批或流式方式。修改与删除明确范围及预期结果，按业务需要检查影响行数；全表操作有明确用途时单独说明，不能仅以有无 `WHERE` 判断安全。
- 每个索引说明它服务的真实 SQL，字段顺序从过滤、关联、排序及分页条件推导，不为所有字段或时间戳机械建索引。对关键或随数据量增长的查询检查执行计划，不要求每条简单 SQL 锁定某个索引名，也不以小样本计划证明生产性能。
- 按数据源与职责复用连接池，配置容量、获取连接及查询的适用超时，所有路径释放事务连接。框架自管连接池与应用池按实际职责保留，不机械合并；退出按 [服务生命周期模块](service-lifecycle.md#退出协调与资源顺序) 接入统一入口关闭资源。
- 明确获取连接、SQL 及整次事务的预算，各阶段受剩余总预算约束；取消或预算耗尽后停止后续业务 SQL／COMMIT，已发出的操作另行跟踪，必要清理仍有界执行。按真实驱动能力处理取消与连接复用，损坏或事务状态不明的连接不得直接归还池中。
- 客户端停止等待或销毁连接不证明 SQL／COMMIT 未生效；结果未知时先核对，不能宣称已回滚或安全重试。迟到资源及未结束操作复用 [生命周期规则](service-lifecycle.md#后台工作与资源所有权)，就绪检查遵循 [探针在途限制](service-lifecycle.md#健康与就绪检查)。
- 连接参数和凭据遵循 [配置模块](configuration.md)，数据库错误与 SQL 参数日志遵循 [日志模块](logging.md)，普通数据库异常按错误模块转换，不泄露秘密或完整业务数据。
- 结构核对、互斥和访问封装按实际风险及现有驱动能力选择，优先复用直接可维护的机制；不强制复制临时参照表、连接包装类或锁实现，也不为满足场景表建设通用数据库框架。

## 实施指引

1. 核对数据库版本、所有权、SQL 基线实际使用范围、驱动及运行入口，确定本次结构与访问变更。
2. 按基线状态选择原稿调整或增量，在 `sql/` 落实脚本与中文注释，接通独立初始化；沿用 DBA 流程、无外键及表结构默认，使用 [开发环境](development-environment.md) 的隔离数据库。
3. 实现必要的参数化访问、类型转换、事务及关联维护，长期规范记录 Schema 流程、类型和比较语义、关联责任、查询与恢复约定，链接脚本和实际验证入口。

## 验收标准

按 [测试政策](testing.md#测试政策) 使用隔离真实数据库与合成数据，选择本次适用范围。替身可验证局部错误处理，不能证明事务、服务器执行或真实驱动接入。

### 重点场景与验证层级

| 范围 | 预期结果及验证方式 |
| --- | --- |
| 基线与初始化 | 按真实使用状态判断冻结，空库初始化与重跑产生正确结构；种子保留用户修改和撤权状态，并发不重复创建。独立入口不启动业务，主程序不改 Schema |
| 表结构与类型 | 主键、唯一及非空等约束符合团队默认与业务例外，中文注释进入支持的数据库元数据；经真实驱动验证数值边界、时间精度及比较语义，涉及时间接入时覆盖非 UTC 默认和会话复用 |
| 增量与恢复 | 用旧结构及代表性数据验证升级与兼容；脚本失败停止后续执行，已完成或可能已提交范围明确，释放资源并非零退出，回滚失败不掩盖原错 |
| 事务与关联 | 经实际业务入口和最终数据验证原子性、适用同库审计、并发关联与删除竞争；提交结果未知不自动重放，执行与清理故障均能安全定位 |
| 访问与连接 | 参数化、动态标识符允许范围及写入结果正确；取消或超时后不继续业务 SQL，连接安全释放或淘汰，客户端返回不作为服务器结束证据 |
| 查询与索引 | 关键查询用代表性数据核对执行计划、排序、分页及索引用途，说明数据规模限制，不宣称已验证生产容量 |

缺少真实数据库或权限时报告未验证项，不连接生产、执行 DBA 变更或清空开发数据。
