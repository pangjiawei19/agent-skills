# 测试与验证

建立或补齐测试组织、运行入口及公共设施，或选择验证方式、调整测试环境和构建冒烟时读取。新工程默认采用独立 `tests/`，按需划分 `unit`、`integration`、`e2e`；已有有效布局、测试政策及语言固有惯例保留。测试与实际验证按行为和风险选择，不以目录、文件或命令存在宣称完成。

## 适用条件与产出

适用于有实际行为或产物需要验证的工程，包括服务、库、前端和独立任务。空工程、文档或工具配置也可进行对应检查，不为满足测试层次创建虚构业务、空成功命令或没有目标的用例。

产出包括实际需要的测试配置、分组与汇总验证入口、隔离环境和数据设施、行为测试或冒烟检查、必要说明及执行结果。框架适配技术栈并优先复用已有工具，各功能模块维护自己的行为验收，本模块统一测试政策与公共执行方式，不重复定义日志、数据库、接口或生命周期契约。

## 测试政策

新工程默认按以下政策选择验证方式，已有工程的明确政策与覆盖率门槛沿用，不静默放宽：

- 可复现的 Bug 优先补回归测试，确认测试能暴露原问题后再修复；无法自动复现时记录验证方法和限制。
- 核心业务逻辑和高风险行为优先测试先行；普通改动选择能够验证其行为的测试。
- 文档、格式及配置调整采用对应检查，不强制新增单元测试。
- 按测试目标选依赖：验证数据库、协议或框架接入时使用真实实现及隔离环境；验证本地行为、模拟故障或涉及付费及不可控服务时可以使用替身。
- 替身测试不作为真实接入已经验证的证据，未覆盖的集成边界在结果中说明。
- 以关键行为、边界和失败路径是否有效覆盖为准，不因已有集成测试就机械要求再补一层同义单元测试。

新工程不统一设置覆盖率百分比门槛，覆盖率用于发现缺口；已有要求保留。关注关键路径及失败分支，不为提高数字机械测试内部实现或排除真正需要验证的代码。目标工程的完整政策维护在已有测试规范中，AGENTS.md 保留必要摘要与带触发条件的链接。

## 组织与运行入口

| 类型 | 目标与适用范围 |
| --- | --- |
| `unit` | 隔离验证业务规则、本地行为及明确的故障处理 |
| `integration` | 验证模块组合、框架、协议或真实依赖接入，不固定只允许一个外部服务 |
| `e2e` | 验证关键用户流程或跨服务链路，明确真实环节与替身边界 |
| 构建与运行冒烟 | 验证实际产物加载、启动及适用基础调用和停止，复用对应模块验收 |

- 只创建当前需要的类别。Monorepo 的单元和集成测试默认放在所属包内，跨包端到端测试放在工程根 `tests/e2e`；Go 同包测试等语言惯例适配保留，不为目录统一破坏工具发现机制。
- 提供适用的分组入口。默认测试运行快速、不依赖外网或真实凭据的用例，不仅限于单元测试；需要数据库、浏览器或外部服务的组分别明确安装、环境及凭据前提，真实调用通过显式入口或开关启用，不因普通开发凭据存在而自动启用。
- 提供汇总格式、静态检查、构建及默认测试的验证入口，复用 [代码质量模块](code-quality.md) 的有效命令；技术栈没有某项检查时按实际能力适配。名称不固定为某种包管理器脚本，CI 接入由 [构建交付模块](build-delivery.md) 负责。
- 每个入口明确发现规则、运行范围、前提及必需检查。目录或组名不能替代真实依赖说明，新增组后核对默认和汇总入口是否包含预期用例；基于变更选择用例时说明未运行范围。
- 选择当前改动需要的验证，按依赖安排准备和执行。检查失败及子进程非零状态传播到分组和汇总入口，不能被包装脚本、管道或清理后的成功状态覆盖。
- 尚无某类测试时如实说明，不建立空成功入口。声明必须运行的组未发现用例、准备失败或全部跳过时返回非零；可选组缺少条件可以显式跳过并报告原因，CI 被选为必需检查的组缺少条件应失败。部分跳过及 flaky 的判定沿用工程既定政策，不将单个工程的严格策略推广为统一门槛。

## 查询与生成命令的产出

通过真实入口检查退出状态及约定的输出通道，核对本次结果的内容、范围和完整性；旧文件或退出零不能单独证明成功。区分合法空结果与遗漏执行，用已知非空输入验证产出路径。处理或写入失败不得发布残缺成功结果，修复后重跑受影响入口。

## 隔离环境、数据与清理

- 首次写入及准备阶段的副作用前，确认实际目标、版本和资源归属属于本次测试或允许复用的范围；无法确认时停止，不能试写未知服务。使用代理或多级依赖时核对实际业务路径，健康检查或端口配置不能代替完整目标确认；目标改变后重新核对。
- 复用 [配置规则](configuration.md) 和 [独立数据库初始化](database.md#schema-脚本与独立初始化)。测试不隐式继承个人配置、生产目标或真实秘密，CI 目标不被本地覆盖；专属夹具不冒充生产 Schema 接入证据。
- 可变数据和状态按用例及运行隔离，覆盖实际共享的身份、会话、线程或配额。独立浏览器上下文和串行执行不能代替后端隔离；确需串行时明确范围并核对最终生效配置，只读依赖可共享。
- 只清理本次拥有或合法接管的资源，独占资源才可整体重置。资源取得或释放结果不确定时先核对，删除前确认当前归属，不能凭旧标记删除已转归他人的同名资源。
- 准备、执行失败后仍清理已获得资源，各项独立清理继续进行，原始与清理错误分别保留。服务先达到就绪条件再运行测试，等待和关闭有界；数据库执行结果及连接状态按 [数据库模块](database.md#sql-访问索引与连接) 判断。
- 测试服务、框架及工具的启停遵循 [统一生命周期](service-lifecycle.md#退出协调与资源顺序)。按需使用公开关闭接口或独立进程，协调工具信号和宿主退出；处理本次活动后代，区分实际执行结束与待回收状态，不终止用户已有服务。

## 替身、断言与可重复性

- 替身放在明确交互边界，保留待验实现和资源路径；真实协议、框架或数据库接入通过相应真实实现验证。替身范围在结果中说明，不为测试强制引入依赖注入框架。
- 使用外部命令替身时核对最终执行环境中的解析路径、归属及可执行性，准备失败不得回退真实命令。所选工具的执行、空间、权限和进程可见性前提在实际运行环境确认，不通过全局清理或降级检查绕过缺项。
- 断言优先检查行为、状态及必要副作用，调用顺序等仅在属于契约时断言。快照用于可审查的输出契约，更新前理解差异；异步行为等待明确条件并设置超时，不靠固定休眠猜测结束。
- 时钟、随机性、环境及有状态夹具按需控制并恢复，避免跨用例污染。核对工具版本的发现、mock 和清理语义；并发、取消或 SDK 接线验证采用受控交接，不能仅以方法返回或 mock 调用证明实际效果。

### 确定性链路与 AI 用例

端到端测试覆盖关键用户流程，可在模型或不可控服务边界使用确定性替身，但保留待验框架、协议、事件及存储路径。AI 用例验证结构化结果、工具行为和最终状态，非空文本只证明有限存活能力。真实模型兼容性与质量评估按需求另行安排，明确成本、凭据和非确定性；替身不证明被替换边界已接通。

## 构建冒烟、重试与结果

- 有可运行产物时通过实际生产入口验证加载、启动、基础调用及停止；库用实际消费者加载。源码、辅助入口、旧服务或部分产物结果不能替代完整交付范围；复用服务前确认版本和测试配置。
- 关闭验证覆盖首次工作后产生的资源，并区分应用按预算退出与测试超时强杀。清理只作用于测试拥有的资源，兜底强杀保留原超时失败。
- 整例重试默认关闭；必要时限定范围与次数，保留首次失败及复验条件。不稳定用例优先修复，临时隔离需说明原因和恢复条件。资源竞争引起的疑似超时先诊断再受控复验，单次成功不证明稳定，不能无依据归因环境或放宽预算和必需检查。
- 分别报告通过、失败、跳过、未发现和未执行，以及命令、实际范围、替身边界和环境限制。必需检查需有属于本次执行的有效证据；空组、全部跳过及缺少前提按前述运行政策失败，退出零或旧报告不能替代。
- 后续修改源码、锁定输入、配置、构建参数或工具环境时，重跑受影响检查；未受影响且输入可关联的证据可保留并说明依据。不仅补写最终 SHA 来冒充本次扫描或产物，也不因提交号改变机械重跑所有检查。
- 诊断与报告遵循 [日志安全要求](logging.md#错误诊断与敏感信息)，仅生成有实际用途的证据，不以数量或文件存在代替结论。

## 实施指引

1. 根据现有政策、工具和本次风险选择最小有效验证，确定实际依赖、目标、输入及副作用范围。
2. 接通需要的发现、分组和汇总入口，准备隔离夹具与清理。新增或修改测试设施时，先通过真实入口验证相关准备失败、目标错配和失败传播，再扩展用例；不预建空测试层次。
3. 复用功能模块的行为验收，按 [交付模块](build-delivery.md) 接入适用 CI 门槛。长期规范记录测试政策、运行入口、隔离与替身边界、跳过和重试策略及验证证据更新方式。

## 验收标准

验证本次涉及的测试能力及下表适用边界。各功能模块的协议、资源和安全契约由其自身维护，组合验收可以共享实际链路与证据，不重复建设验证设施。

### 场景与验证层级

| 范围 | 预期结果及验证方式 |
| --- | --- |
| 发现与失败传播 | 从真实分组及汇总入口确认预期用例实际执行；合法基线通过，目标故障导致预期失败，空组、缺条件及跳过按政策处理，无关故障不充当有效反例 |
| 实际产出 | 查询或生成命令的本次输出符合约定，已知非空、合法空结果及失败路径可区分，修复后重跑 |
| 环境与隔离 | 实际业务路径到达已确认目标；准备写入前可拒绝受控错配，重复及并行运行不污染开发数据或其他测试状态 |
| 资源清理 | 新增或修改测试设施时，通过实际工具、客户端或进程验证相关取消、准备失败及清理失败；归属不确定时不误删，结果与退出状态准确 |
| 行为与接线 | Bug 回归能暴露原问题；真实接入保留待验实现，确定性替身只替换声明边界，关键失败和状态变化有可观察结果 |
| 最终证据 | 实际产物通过适用冒烟；报告保留首次失败、复验条件、跳过与限制，修改后证据仍对应最终输入 |

使用隔离资源与合成数据，不因验收连接生产、读取真实秘密或触发付费调用和对外通知。分别报告公共设施、真实依赖、完整工程和外部平台的验证范围。
