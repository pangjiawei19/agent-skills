# 代码规范与质量检查

为工程确定代码风格、配置格式化和静态检查工具，或补齐检查与修复入口时读取。本模块规定协商和落地流程，不指定具体代码风格、工具或规则预设。

## 适用条件与产出

适用于需要统一代码风格和自动检查的工程。按语言、文件类型及框架能力选择格式化、静态检查和类型检查；无需为了满足模块清单而增加不适用的工具。

产出包括用户认可的规则配置、实际可运行的检查与自动修复入口、工程长期代码规范及验收结果。已有有效配置时沿用；只有缺项、实质冲突或用户要求调整时重新讨论。

## 先与用户商定

### 检查已有约定

读取已有工具配置、编辑器配置、脚本、CI 入口及适用规范，结合少量实际代码判断当前实践。区分已明确的规则、工具隐含默认值和代码中的偶然写法，发现冲突时先说明。

用户在当前会话已确定的选择直接沿用，不重复提问。没有既定约定时，完成以下讨论后再写入风格配置。

### 提出可评估的方案

根据技术栈提出具体方案，包含：

- 建议的工具、适用文件范围及各自职责，例如格式化、错误检查和类型检查。
- 建议采用的风格预设，以及影响阅读和协作的关键选项；需要时用简短示例展示差异。
- 规则强度、检查失败条件、忽略范围，以及已有代码可能产生的调整量。
- 剩余选项准备沿用什么预设，不逐项询问所有工具参数。

可以推荐生态默认方案，但必须说明并取得用户认同后采用；用户也可以明确授权 Agent 在给定范围内决定。已有配置可作为方案本身，不因使用本 skill 而重新选型。

意见未确定时，继续收集配置与影响范围等不依赖该决定的信息，暂不实施依赖该选择的配置或批量修复。决定后按已认可范围执行，无须为每条规则重复确认。

## 落实为工具配置

- 将决定写入目标技术栈支持的配置位置，并确保命令实际读取它；采用具名预设时记录预设来源，按开发环境模块管理工具和规则包版本。
- 同一规则优先由一个工具负责，格式化、静态检查和编辑器自动保存行为保持一致。必要的覆盖项明确理由，避免工具交替改写同一段代码。
- 提供只检查、不修改源文件的入口，以及单独的自动修复入口。检查发现达到约定失败条件的问题时以失败状态退出，不能吞掉错误或只打印成功信息。
- 明确检查的文件范围。生成代码、第三方代码及构建产物按实际情况排除；检查范围应覆盖约定维护的源码和测试，避免误将整个业务目录忽略。
- 按实际文件类型明确各工具的覆盖与缺口，分别核对解析、类型检查及测试运行环境；测试发现和环境遵循 [测试模块](testing.md#组织与运行入口)。
- 按工具实际解析规则验证维护文件被检查、生成物被排除，避免宽泛忽略遮蔽源码；工具之间不互相替代覆盖证据。
- 编辑器与命令行复用已确定规则，保留语言及文件类型例外；接入或修改编辑器配置时比较实际输出，缺少条件则说明未验证。
- 工具无法表达的命名、注释或业务约定，才补充到适用的规范中。文档说明使用方式和必要取舍，不复制整份工具配置。
- 规则例外优先局部豁免并说明原因。需要调整整类规则时，回到已确定的规则目标讨论，不为通过检查静默关闭它。

## 执行时机与修复范围

- Agent 完成代码修改后，主动执行适用检查并处理本次修改引入的问题。
- CI 复用同一配置及检查入口，将适用检查作为合并门槛。具体流水线与平台限制按 [构建交付模块](build-delivery.md) 接入及核对；尚未接入时明确记录，不将本地命令存在描述为门槛已生效。
- 本地提交钩子可选，已有有效配置可以保留；新增钩子根据用户选择启用，不默认要求每次提交运行完整检查。
- 自动修复后检查差异，并重新运行适用检查。可能影响语义的修复需要相应验证，不能仅凭工具退出成功认定行为不变。
- 默认只处理本次任务相关范围。首次引入规范导致全库格式变化，或已有历史问题影响检查时，先说明影响及候选处理方式，由用户选择集中修复或明确的过渡方案，不夹带大范围改写。
- 局部检查仅用于其能够可靠覆盖的任务；全工程类型分析等依赖整体上下文的检查保持必要范围。存在历史阻塞时如实报告，不能用只检查部分文件宣称整个工程通过。

## 实施指引

1. 核对已有配置与实际代码，按前述流程商定确需调整的方案，已有决定直接沿用。
2. 依据实际工具版本接通配置、检查与修复入口，在认可范围内修复并审查差异；CI 接入仅在本次范围包含时实施。
3. 长期规范记录规则选择、工具职责、维护范围及例外，链接实际配置和命令，遵循 [统一交付要求](../SKILL.md#统一交付要求)。

## 验收标准

检查与已认可方案一致，使用隔离合成样例，不修改任务外源码。遵循 [测试政策](testing.md#测试政策)，空检查不能作为完成证据。

### 重点场景与预期结果

| 检查范围 | 预期结果 |
| --- | --- |
| 覆盖与排除 | 从实际入口确认应维护文件被发现、生成物被排除，新增类型具备声明的检查及运行环境；缺口显式说明 |
| 规则与失败传播 | 合法基线先通过，目标违规产生可归因的诊断和失败；配置错误、空扫描或无关异常不充当有效反例 |
| 检查与修复 | 检查不修改源码，修复后通过适用检查，再次格式化不反复改写；语义变更有相应验证 |
| 编辑器与 CI | 本次涉及编辑器接入时比较实际输出；涉及 CI 时验证调用和失败门槛，未验证的外部条件分别说明 |

重要且易回归的覆盖边界按需纳入回归，文档或简单设置用对应检查，不新增只匹配文案的测试。
