# 构建、交付与部署

## 适用条件

适用于建立构建产物、镜像交付和 CI 的工程。新建常驻后端默认使用 Docker 镜像；已有工程保留有效交付方式，静态前端、库及一次性工具按实际运行或发布方式适配，不为统一形式额外建立常驻服务。

团队 CI 默认采用 GitLab CI，完成验证、镜像构建及冒烟、推送 AWS ECR 和飞书通知。代码仓库不执行部署：不生成部署或回滚 Job、生产 SQL 执行入口，也不在流水线调用 kubectl apply、helm upgrade 或部署平台发布接口。仓库提供产物记录与运行交接说明，实际部署、发布后验收和回滚由外部平台负责。

## 规范与要求

### 交付形态与组件边界

- 在编写 Dockerfile 和 CI 构建 Job 前，按独立发布、扩容、运行权限和团队维护边界确定最小必要产物，记录选择依据；源码包、进程和镜像数量不必一一对应。已有有效形态保留，不直接照搬参考工程的多镜像或单镜像方案。
- 前后端发布节奏及运行边界一致的工具应用可以由 Server 托管前端；需要独立发布、扩容或隔离时分别交付。多产物明确兼容组合及消费者，单产物同样验收其全部运行能力，不以减少镜像数牺牲已确定边界。

### 构建与运行产物

- 构建可重复，明确工具链、参数、产物和生产入口，本地与 CI 复用 [质量检查](code-quality.md) 及 [测试](testing.md) 入口。
- 锁定依赖覆盖安装、生产裁剪及最终打包；重新解析或生成部署锁文件时保留可追溯约束。从最终产物核对运行依赖、内部包链接及资源路径，原生扩展和系统工具在目标运行时、操作系统及架构实际可用。
- 构建与运行分离，Docker 默认多阶段构建，明确 target、启动命令及目标平台。基础和工具镜像有明确版本，按需固定 digest；运行用户默认非 root，写入权限和信号传递符合运行要求。
- 运行产物只包含必要内容，`.dockerignore` 排除秘密、开发资源及缓存。私有依赖凭据通过 BuildKit secret 等临时机制注入，不进入镜像层、日志、缓存或产物。
- 用实际交付产物和生产入口完成适用加载、核心调用及停止冒烟，核对所需宿主能力；缺少必需依赖不能静默跳过。仅构建成功或文件存在不足以证明可运行。

### 同进程静态托管

仅在 Server 托管前端时，验证实际生产路由与浏览器行为：SPA 深链可回退，未知 API 和缺失资源保持错误语义；隐藏文件默认不公开，缓存符合资源及敏感性要求。静态通配不绕过认证、不覆盖 API 路由及稳定观测标签；完成与排空遵循 [生命周期](service-lifecycle.md#退出协调与资源顺序) 和 [指标口径](metrics.md#http-与外部调用)，开发代理不能代替生产接线。

### 版本与交付记录

- 通过检查的源码、构建输入和交付产物对应同一完整提交及本次流水线，验证后不切换输入或复用来源不明的旧产物。
- 交付使用唯一且不覆写的 tag，参考 `release-组件-Job编号-短SHA`；以机器可读记录保存完整 SHA、流水线及构建 Job、UTC 时间、组件、target、平台、URI、tag 和远端 digest。ECR 推送后确认 digest，外部部署优先使用 digest，跨环境复用同一产物，并保留可追溯记录。
- 扫描和冒烟针对本次不可变镜像，推送前确认 tag 仍指向同一对象；区分本地 Image ID 与远端 manifest digest。扫描适配器须把报告实际对象与请求对象及本次产物比较，格式合法或外层补写身份不能代替真实匹配；无法关联时必需检查失败。
- 多组件逐项记录，全部必需组件及检查成功才可汇总成功。部分上传保留成功产物及失败阶段，网络不确定时记录未确认状态。
- 写入、汇总和通知共用记录契约，校验组件、版本、产物、结果及可信 artifacts 来源一致；汇总 Job 不冒充构建 Job，格式校验不能代替来源证明。采用附带脚本时沿用其完整契约，不补造缺失证据。

### GitLab CI 触发与结果

新工程采用以下默认规则，已有工程保留有效触发约定：

| 事件或分支 | 执行范围 |
| --- | --- |
| Merge Request | 适用源码安全扫描、锁定安装、格式与静态检查、构建和默认测试 |
| develop | 同样执行验证 |
| release/* | 同样验证；默认仅受保护分支的 push 流水线在检查通过后构建、冒烟、镜像扫描、推送 ECR、校验记录并通知 |
| 其他分支或标签 | 默认不触发，明确需要时再补充规则 |

- workflow 与 Job rules 明确事件及分支组合。参考模板允许 develop、release/* 分支验证与 MR 验证分别运行；MR 不因分支名称匹配 release/* 获得推送权限。
- 发布限定可信事件、受保护引用及认可分支，脚本检查与 Runner、云身份、平台权限共同生效。验证 Runner 不向不可信 MR 提供上传身份或秘密，屏蔽变量不能代替权限隔离。
- 必需检查失败阻止交付，复用既有验证入口。源码依赖及秘密扫描进入验证阶段，镜像冒烟与扫描进入实际产物阶段；采用推送后扫描时，完成门槛前不得宣称可交付。扫描要求由 [安全模块](security.md#依赖安装脚本与安全检查) 维护。
- 外部操作前校验本地可确定的参数和秘密映射。命令失败、取消和清理状态真实传播，原始失败不被后续成功覆盖，通知单独判定。
- Runner 明确工具镜像版本、Docker／BuildKit 连接、目标架构和预算；自建工具镜像有可用的首次发布及 MR 拉取路径。在实际工具容器核对 [运行前提](testing.md#替身断言与可重复性)，宿主检查不能替代。
- AWS 身份复用 Runner Role、临时凭据或受保护变量，ECR 区域、账户、仓库和权限由已有设施提供，不创建云资源或改造 IAM。并发构建及清理仅处理本次资源，不全局 prune。
- 命令取消、子进程与临时认证目录清理留有总预算余量；本地客户端停止不证明 daemon 或远端操作已取消。附带命令入口的操作系统和进程查询限制见其源码，其他执行器按实际能力适配。
- 核对 GitLab 必需检查、合并门槛、受保护分支、Runner 及变量可用性；YAML 不能证明平台权限已生效，无法访问时交付待配置及未验证项。

### 飞书通知

- 通知表达验证或交付结果，包含项目、分支、完整提交、组件结果、产物及 digest、流水线链接，不称为已部署或已上线。
- 有限超时和重试，核对 HTTP 及飞书业务结果。通知失败独立告警并保留原交付记录，补发复用原记录，不触发重建或改写构建结果。
- 成功汇总严格验证；失败通知保留仍可信的组件记录，用安全摘要说明损坏或来源异常，不泄露坏记录正文，不据此恢复整体成功。
- Webhook 与签名密钥由 CI 注入，载荷有界且不泄露秘密；搭建模板和离线验证不发送真实消息。

### 外部部署交接

仓库维护简洁的交接文档，按实际内容记录：

- 各组件产物 URI 与 digest 的获取方式、启动命令、架构、兼容版本及发布顺序。
- 必需配置与密钥来源、端口、网络访问、资源与系统权限前提、持久化及挂载目录。
- 按 [安全模块](security.md#http-与浏览器防护) 记录 TLS、可信代理及适用访问控制的前提，由外部平台接入实际配置。
- 存活、就绪及按需启动探针，摘流及终止宽限期与应用关闭预算；指标采集入口、访问与实例发现要求。语义分别引用 [生命周期模块](service-lifecycle.md) 和 [指标模块](metrics.md)，由外部平台接入实际配置。
- SQL 前提、DBA 执行顺序、旧数据和新旧应用兼容窗口，引用 [数据库模块](database.md)。主程序启动不创建或修改 Schema；CI 可通过独立初始化入口准备隔离测试库，目标确认与资源归属遵循 [测试隔离要求](testing.md#隔离环境数据与清理)，不执行生产 SQL。
- 外部平台部署后需要检查的真实行为，以及回退到旧产物时的数据与配置兼容限制；不把切换旧镜像解释为自动逆转 SQL 或业务数据。

不固定 Kubernetes、Compose 或某个部署系统，仓库不增加可执行部署及回滚流程。外部发布状态与 CI 交付状态分别记录。

## 实现指引与参考模板

1. 检查已有构建与交付约定，确定最小产物、运行边界和平台前提，复用有效入口，并执行适用基线扫描。
2. 落实最终产物、冒烟及 CI 门槛，长期规范记录产物选择、发布权限、版本追溯和外部部署交接，遵循 [统一交付要求](../SKILL.md#统一交付要求)。
3. 采用附带模板时，将 [GitLab CI 模板](../assets/build-delivery/gitlab-ci.yml) 适配为 `.gitlab-ci.yml`；将 [镜像构建](../assets/build-delivery/build-image.sh)、[记录写入](../assets/build-delivery/build-record.py)、[汇总通知](../assets/build-delivery/notify-feishu.py)、[共享记录契约](../assets/build-delivery/delivery_contract.py) 和 [命令执行](../assets/build-delivery/run-command.py) 五个脚本一同放入目标工程 `scripts/ci/`。同步适配所有本地依赖，不依赖 skill 安装路径。

以下仅在采用该模板时读取。流程为 `source-scan → verify → build-image → collect-images → notify`；镜像阶段包含冒烟、扫描及推送，汇总为必需门槛，通知允许独立失败，`--collect-only` 不发送消息。

| 配置组 | 适配要求 |
| --- | --- |
| Runner 与工具镜像 | 落实 `CI_VERIFY_RUNNER_TAG`、`CI_BUILD_RUNNER_TAG`、`CI_VERIFY_IMAGE`、`CI_BUILD_IMAGE`、`CI_NOTIFY_IMAGE`；具备模板使用的 Bash、Python 3、项目工具及适用 Docker、AWS CLI、扫描器，满足前述身份隔离与首次拉取条件 |
| 验证、扫描及冒烟 | 提供真实 `CI_VERIFY_COMMAND`、`CI_SOURCE_SCAN_COMMAND`、`CI_IMAGE_SCAN_COMMAND`、`CI_IMAGE_SMOKE_COMMAND`；扫描写入 `CI_SCAN_REPORT_DIR`，镜像扫描和冒烟使用本次 `CI_IMAGE_ID`／`CI_IMAGE_URI` |
| 产物与预期清单 | 配置 `AWS_REGION`、`ECR_REGISTRY`、`ECR_REPOSITORY`、`IMAGE_COMPONENT`、`IMAGE_TARGET`、`IMAGE_PLATFORM`、`DOCKERFILE_PATH`、`BUILD_CONTEXT`；`EXPECTED_IMAGE_SPECS` 按组件声明 repository、target、platform，与 matrix、needs 及 artifacts 来源一致 |
| 秘密与通知 | 按需配置 `CI_BUILD_SECRETS` 的 `id=名称,env=变量名` 映射及 Dockerfile secret mount；注入 `FEISHU_WEBHOOK_URL` 和启用签名时的 `FEISHU_WEBHOOK_SECRET`，不填写真实值到示例 |
| 预算与保留 | 依据 Job 时限适配 `CI_COMMAND_TIMEOUT_SECONDS`、`CI_COMMAND_STOP_SECONDS`、`CI_ECR_DIGEST_ATTEMPTS` 及 artifacts 保留期；默认值、合法范围和记录版本以所链接脚本及模板为准，正式版本记录需长期可追溯 |

模板支持单组件、单 Linux 架构；多组件同步调整预期清单和依赖，多架构需适配构建、索引及冒烟，其他交付方式不强套 ECR。更新时脚本、模板和记录格式一起核对兼容性；GitLab 元信息使用实际产生记录的上下文。

扫描使用新的隔离报告目录。通用脚本只检查非空报告并补写外层身份，具体扫描器适配命令仍须验证报告对象、范围、发现及安全门槛；不能用空命令或旧报告通过检查。命令包装器的进程识别和停止机制是参考实现，采用时需在目标 Runner 验证，不推广为其他工程的通用设计。

## 验收标准

按 [测试政策](testing.md#测试政策) 验证本次改动及适用边界。仓库附带脚本的离线回归证明编排行为，不能代替 Docker、GitLab、ECR 或飞书实际接通。

### 重点场景与验证层级

| 范围 | 预期结果及验证方式 |
| --- | --- |
| 最终产物 | 实际生产入口通过加载、核心调用和停止；依赖受锁定约束，资源、架构、权限及适用前端托管正确，秘密不进入产物 |
| CI 与权限 | 校验真实版本的 CI 语法及触发组合，必需检查失败可传播，MR 无发布身份；平台配置与仓库配置分别确认 |
| 交付与扫描 | 通过实际适配入口验证合法报告及对象错配、缺项或扫描失败；错误阻断交付，所有成功记录可追溯到本次产物和远端 digest |
| 失败与清理 | 新增或修改编排时验证相关阶段失败及取消，原错误保留、本次资源被处理；部分推送或未知结果不能汇总成功，目标 Runner 上验证停止能力 |
| 汇总与通知 | 损坏记录不放宽成功门槛，失败汇总仍保留有效组件且不泄密；通知失败独立处理，不触发重建 |
| 外部交接 | 交接覆盖实际运行、SQL、平台验收及回退限制；仓库无部署、回滚或生产 SQL 执行，CI 测试初始化仅作用于已确认隔离目标 |

真实推送和通知仅在已授权且条件具备时执行。分别说明本地、平台权限、远端产物、通知送达及外部部署状态，缺少条件不宣称全流程完成。
